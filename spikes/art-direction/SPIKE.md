# 探针：美术和界面方向

## 问题

低多边形玩具城能不能用代码做完全部素材？地块、物业、道路负担、公共服务、昼夜和风格包这些规则，能不能落到同一套数据和素材结构上？四级道路、立交、高架快速路、公共交通和动态车流能不能在这套结构上跑起来？地图放大到 128×128 要付出什么代价？

## 时间盒

九轮。第 1 到 3 轮定风格和配色，第 4、5 轮按用户新规则重做，第 6 轮修路面、重做街区划分、加道路体系和模块拼装实验，第 7 轮修切法打分、切坡两端、大三角的楼，第 8 轮做路口规划、立交线形、默认城市高架、统一遮挡、交通视图、公共服务、地铁公交和征收，第 9 轮把默认地图定为 128×128，按这个尺寸收掉遮挡、路面、车道和性能问题。

## 不管的事

音效、全部素材、数值平衡、铁路、机场、海港、完整的线路编辑。

## 怎么运行

```
pnpm install --ignore-workspace
node scripts/verify.js        # 纯计算的验收检查，不通过时退出码是 1
node scripts/rampcheck.js     # 匝道坡度和立交圈内用地，不开浏览器
node scripts/slopecheck.js    # 切坡路基的像素检查，不开浏览器
node scripts/lotcheck.js      # 大三角物业的占地检查，不开浏览器
node scripts/partition.js     # 街区划分的前后对比
node scripts/replan.js 128    # 改一条路之后的增量重算，不开浏览器
node scripts/preview.js lots|modules|tee|diamond|viaduct|center  # 软件光栅的形体预览，不开浏览器
node scripts/gen.js           # 烘三套调色的图集，含 32、64、128 用到的全部精灵；node scripts/gen.js sunny 只烘一套
node scripts/budget.js        # 推算全部素材，要先有 sunny、dusk、dayOnly 三套烘焙结果
node scripts/occlusion.js 300 128  # 遮挡顺序验收，要先有 out/atlas-sunny.json
node scripts/ixcheck.js       # 丁字和菱形，出 r8-ix-tee、r8-ix-diamond、r8-ramp-merge、r8-ramp-cars
CITY=1 node scripts/ixcheck.js ix-city-report  # 默认城市里的立交和高架
node scripts/junctions.js     # 路口验收，128 全图，出 r8-junction-sheet、r8-slope
node scripts/deckcheck.js     # 路面细线，出 r8-deck-zoom
node scripts/roadcheck.js     # 路面渲染遮罩验收，128 全图按 64 格见方分块
node scripts/lanes.js         # 只查高架和立交的车道
node scripts/sheets.js        # 成品样张，默认 128，SIZE=64 出 64 的
node --max-old-space-size=900 scripts/big.js   # 64 和 128 的生成和存档测量
pnpm serve                    # http://localhost:4180/
```

`verify.js`、`slopecheck.js`、`rampcheck.js`、`partition.js` 的地图尺寸写死在文件头上，默认 64（`verify.js` 是 32 和 64）。下面 128 的结果是把这个常量换成 128 跑的。

`SEAM=1 node scripts/shots.js` 跑露底和网格线检查，`FPS=1 node scripts/shots.js` 测帧率，加 `SOFT=1` 用软件渲染。`gen.js` 的输出不要接 `head`：管道一关进程就停，图集只写到一半，管道的退出码还是 0。根目录 `pnpm format` 会把 `out/` 里的 JSON 也格式化。

`web/play.html` 的参数：`n=128` 地图边长（默认 128），`scene=interchange` 四级道路场景，`view=traffic|coverage|metro` 三种视图，`cars=300` 车辆上限（0 关闭），`full=1` 视野里一直保持满额的车，`t=22` 时间，`icons=0` 不画公共服务图标，`stress=3` 每个物业画 3 遍。

这台机器物理内存 15GB。开浏览器的步骤一次跑一项，开之前看可用内存不低于 3GB。

## 路面

路面用距离场在片元里画，一格的精灵会盖到邻格，所以拼接靠三条规则：

1. 全图分三层画：所有人行道、所有路缘、所有车道。后画的盖先画的，人行道不可能出现在车道上。
2. 裁剪按整条路做，不按线段做。
3. 路口圆角来自各方向沿直线延长后的平滑并集，对向的两个方向算一条直线。延长线到邻格中心为止：路在邻格可能转弯或收成丁字，长到 1.5 格会伸到没有路的地方，丁字路对面的草地上多出一圈 U 形细线。

路口垫片和邻格直路在两张精灵上，半透明的边叠不满时下层会透上来，看起来是一条细线。两张精灵多盖 0.03 格（`PAD_OVERLAP`）后叠满。

实心像素必须不透明。烘焙累加几十次光照，半浮点把小权重加到 2 时舍掉将近 1%，累加出来的 alpha 只有 253，颜色除以 alpha 后还亮 3 级。所以 alpha 不累加，取最后一次渲染的覆盖率。

切坡的做法：台地四周是连续直坡；连续坡段的路面按整段匀速升降；挡墙和填方沿整段连续，填方等宽；切线为 0 的一头是坡段端点，挡墙高度、填方宽度和落差在这一格里平滑收到 0。

坡上只放得下直路。转弯和路口的路面贴着这一格的地形，精灵超出格子的部分和邻格错开；默认城市的布局绕开了这种情况，上台地的路在台地顶上的平地收尾。

## 路口

斑马线两端接人行道，灯杆立在路缘外，停车线按车身长度算。相邻路口共用一格时斑马线不进另一个路口。五向以上做环岛。

信号灯八个方向各一张灯杆，灯面只有朝相机的 3 个方向各一张，背面不亮。灯杆立在进口右侧，悬臂伸到车道上方。这 11 张精灵的总面积约 3000 像素。

车道转弯的控制点是两条车道线的交点。45° 的弯里车道和路面中线保持车道偏移的距离，高速弯道上是 0.29 格；两个偏移直接相加只在 90° 弯成立，算出来是 0.40 格，正好压在路面边上。

`scripts/junctions.js` 在真实烘焙拼出来的遮罩上查 15 类路口和 128 全图，全部通过：

## 路面细线

`scripts/deckcheck.js` 用专门的配色烘焙：人行道和路缘白色，标线和路面同色，路面上剩下的任何颜色都是漏出来的。离路面边 0.035 格以内不查，亮度差上限 2（0 到 255）。查 12 个验收样例和 128 城市里每一种不同的路口，135 种组合，2109 万个采样点，脏像素 0。

alpha 累加的旧烘焙下 74 种组合有 1895 个脏像素，都是叠两三层路面的地方和叠一层差 2 点几，证明查得出来。五向以上是环岛，环岛区不查。

## 立交

玩家只画线，路线相交时系统按等级选模板。线形是直线加圆弧，路面宽度沿中心线变化，右行规则下合流分流都在主线右侧的平行车道上。桥面高度 1.25 层，一层是 1/√6 格。

| -------- | --------------- | -------- | ---- | -------------------- |
| 丁字     | 11 × 9，99 格   | 51 格    | 4    | 交付                 |
| 菱形     | 7 × 11，77 格   | 28 格    | 4    | 交付                 |
| 半边菱形 | 3 × 10，30 格   | 6 格     | 2    | 交付                 |
| 快速路头 | 10 × 3，30 格   | 9 格     | 2    | 交付                 |
| 苜蓿叶   | 17 × 17，289 格 | 176 格   | 8    | 未完成，第一版不交付 |
| 喇叭形   | 17 × 15，255 格 | 173 格   | 4    | 未完成，第一版不交付 |

圈内空地连得到普通路的还给城市：每片一个停车场，其余按低密度商业交给地块生成器。连不到普通路的留作绿地。默认城市 2 个停车场、7 个小物业（容量 54），出入口全部接普通路，压车道 0；两个反例都抓得到。

`scripts/ixcheck.js` 查八项（同高相交、桥墩压路、转角超过 8°、侧面露缝、车开到路肩上、车道有洞、开口隔着路缘、车偏离车道中线），丁字、菱形和默认城市的半边菱形、快速路头、丁字全部是 0。车中心到车道中线最大 0.05 格，上限 0.08。默认城市高架主线 11 格：路格里的桥墩 0，净空不足 0，主线下面的物业 0。

分岔口要注意两件事。主线和匝道可能只叠一角，排序看三条视线。一块桥面画出占地的部分排序看不见，所以主线节点 0.1 格一个，接缝只多画 0.2 格；节点半格一个时多画一格，主线的路肩盖到隔壁格的匝道上，菱形立交有 30 个压路肩的采样。

`scripts/lanes.js` 交付范围全部通过。贴地的车道从桥下穿过时，屏幕上那一点读到的是桥的路肩，检查再读一次不画结构的遮罩，那里是车道就不算压路肩。把采样推到路肩外的变异版本 tee 这一行报 50 个，检查还抓得到真问题。

车在坡上的倾斜有两种做法。烘焙要给每个方向再烘几档坡度，8 个方向 4 种颜色加公交的 40 张要翻几倍。运行时旋转不加精灵，车头跟路面走向连续变化，换精灵时不跳，选的是这种。代价是偏离 8 个方向最远时车身会变形，弯道上看得出，见 `out/r8-ramp-cars.png`，要改善就加到 16 个方向。

## 高架快速路

默认城市有一条高架快速路：从高速的快速路头爬上去，贴着一条南北街穿过城区，东侧一对匝道落到短街，再落回地面收成四车道接进横街的信号路口。快速路分地面和高架两种形态，同等级、同运力，造价系数地面 2、高架 6（每格，相对地面四车道，临时值）。形态只影响造价和画法。

主线占一列格子，路格里不立桥墩。西侧紧贴南北街放不下南向匝道，所以南向只在两头进出。样张 `out/r8-viaduct-city.png` 有全景、上下匝道、跨路口、引道过渡和落地，白天和夜里各一排。

## 遮挡

全城一份绘制序列：地面、路面先画，然后车、灯杆、建筑、桥墩、桥面混排，桥面上的车在桥面后面。公交按车身占地算。规则写在 `web/sim/order.js`。每帧把视野和周边一圈的静态物体和车一起做拓扑排序，静态物体之间的边只算一次，见 `web/sim/drawlist.js`。

## 交通分配

住宅是起点，商业和工业是终点，起点的出行量按终点容量除以距离平方分配，沿行程时间最短的路走。快路单位时间短，所以长距离的出行自己绕到快路，上下快路要经过匝道。地图边上的三个出入口也是起点，出行量是全城终点容量的 25%。

| 等级   | 容量（临时值） | 单位时间（临时值） |
| ------ | -------------- | ------------------ |
| 普通路 | 900            | 1                  |
| 四车道 | 1800           | 0.8                |
| 快速路 | 3000           | 0.35               |
| 高速   | 3600           | 0.3                |
| 匝道   | 1500           | 0.7                |

| 地图 | 路段 | 出行量 | 走不到 | 过载路段 | 最忙负荷 |
| ---- | ---- | ------ | ------ | -------- | -------- |
| 64   | 714  | 4306.5 | 0      | 0        | 0.56     |
| 128  | 4035 | 29060  | 0      | 173      | 1.86     |

128 的出行量是 64 的 6.7 倍，过载 173 段，城中心的路在交通视图里大片发红。容量是临时值，这一项留给数值阶段。

交通视图路面按负荷染色，宽度就是路面宽度，箭头沿方向流动，流速表示拥堵；点一个物业才显示门到路的箭头和它的车走的路。缩放小于 0.2 不画箭头，128 放大时 8155 个箭头。样张 `out/r8-traffic.png`。

## 公共服务

每种服务有专用色，饱和度比分区颜色高，普通物业不用，`verify.js` 核对色差，最近 56，下限 45。图标牌在建筑上空，全图时放大到认得出，放大时不跟着放大，缩小时按屏幕距离避让。样张 `out/r8-public.png`。

| 地图 | 用地分散时住宅盲区 | 全集中时 |
| ---- | ------------------ | -------- |
| 64   | 34%                | 87%      |
| 128  | 82%                | 100%     |

128 全图 41 个图标，64 是 17 个。盲区的原因没有细查，公共服务的数量没有跟上城区面积是最可能的一条。

风格包约定：换风格时公共服务的专用色和 `si-` 图标牌不换，别的物业不能用这些颜色。

## 地铁和公交

地铁 3 条线，1 个环，不分叉，2 个换乘站，1 处穿过不设站。隧道最小转弯半径 2 格。线路图和实际走线是同一条线，折线放不下圆弧时记下来提示玩家。站厅各占一格，放在路边，入口朝人行道。样张 `out/r8-metro.png`、`out/r8-stations.png`。

`metroPlan` 按第几条街取线路，128 的街是 64 的 3 倍，环线挤在地图西北角，两条线沿城北贯穿全图，到不了市中心。线路规则本身不受影响。

公交站 64 城 138 个、128 城 880 个，在路格的人行道上，不占地块。公交经过站台时停在格子中央，停够时间再走，后面的车等。

## 征收

地铁站、公共用地、新修的路落到已有建筑上走同一个流程：先显示拆几栋、影响多少人、付多少钱，确认后才生效；居民一个游戏日内陆续搬走，楼拆除后再建。连体物业是一个地块，压到一格整块处理。费用每人 12、每格 40，临时值。默认城市的样例：拆 1 栋，影响 16 人，352；半天后还剩 8 人，一天后可以开工。

## 土地模型和街区划分

每格被两条对角线分成 4 个原子，每个面积正好 0.25。所有地块都是原子的并集，容量 = 原子数 × 分区等级费率，全部是整数运算。

街区划分在 `web/sim/partition.js`。规格表里有的完整形状并且贴普通道路，就整块成为一个物业；否则沿 0°、45°、90° 的格线递归切分。打分权重在 `web/sim/partition-weights.js`。建筑不贴普通道路就不长；切剩的边角是绿地。

划分按街区缓存，键是原子加每原子沿街边长。`planPartition()` 返回任务，`run(budgetMs)` 每批解几个街区就停。`node scripts/replan.js 128`，量的时候另有一个浏览器在跑，时间偏长：

| 项目                 | 街区 | 重算 | 总时间  | 单块最坏 |
| -------------------- | ---- | ---- | ------- | -------- |
| 冷启动               | 371  | 371  | 67.1 秒 | 528 毫秒 |
| 横穿全城画一条新路后 | 380  | 53   | 8.7 秒  | 459 毫秒 |
| 同一条路，不用缓存   | 380  | 380  | 63.8 秒 | 437 毫秒 |

8 毫秒预算分 38 批，结果和不用缓存完全一致。单块是递归动态规划，不能在块内中断，最坏一块卡一帧，要真不阻塞得放 Web Worker，或者调小 `BLOCK_BUDGET`、`MAX_REGION` 换质量。

## 帧率

设备：AMD Ryzen 9 7940HS 笔记本，物理内存 15GB，测试时可用约 4.6GB。视口 390×844。每项测 5 秒。车数是回报的实际数。游戏视角是缩放 0.42，视野内约 550 个静态物体。

| 用例                | 车数 | 显卡 p50 | p95 | 最差 | 软件 p50 | p95  | 最差 |
| ------------------- | ---- | -------- | --- | ---- | -------- | ---- | ---- |
| 128 鸟瞰全图        | 0    | 156      | 115 | 74   | 25.1     | 20.1 | 18.0 |
| 128 半图缩小        | 0    | 154      | 111 | 71   | 15.9     | 14.2 | 12.5 |
| 128 游戏视角        | 300  | 64       | 54  | 27   | 13.0     | 10.8 | 9.8  |
| 128 游戏视角        | 150  | 102      | 83  | 72   | 13.0     | 10.8 | 10.3 |
| 128 游戏视角        | 100  | 137      | 111 | 94   | 12.9     | 11.1 | 10.4 |
| 128 夜间车灯        | 300  | 65       | 53  | 33   | 13.2     | 10.8 | 9.1  |
| 128 交通视图        | 0    | 161      | 103 | 74   | 12.1     | 9.5  | 8.7  |
| 64 游戏视角（对比） | 300  | 69       | 59  | 50   | 12.7     | 10.2 | 9.2  |

显卡是 Radeon 780M 集成显卡，D3D11，3 倍像素比，关垂直同步和帧率上限；软件是 SwiftShader，1.5 倍像素比，只靠 CPU。

怎么看这些数字：

- 显卡一列是 `requestAnimationFrame` 的速率，只能看相对差别。
- 地图大小基本不影响游戏视角：128 和 64 差 5 帧，每帧只处理视野和周边一圈。
- 车是主要开销。300 辆一帧约 15.6 毫秒，150 辆 9.8 毫秒，100 辆 7.3 毫秒，其中排序 7.4、5、4 毫秒。
- 软件渲染卡在像素填充上，游戏视角 100 到 300 辆都是 13 帧，车数不是瓶颈。
- 这些都不是手机数字。第一版的目标是中端手机竖屏 30 帧，这一轮没有真机。

手机默认车数上限建议 100，高端机放到 150，300 只留给桌面调试。这是推算：手机 CPU 按这台的 3 到 4 倍慢算，300 辆光排序就 22 到 30 毫秒，已经吃掉 30 帧的 33 毫秒；150 辆 15 到 20 毫秒，留给组装和绘制的不多；100 辆 12 到 16 毫秒，放得下。上限要在真机上再定一次。

牵动的文档，按需要改动的方向列出，没有决定：

## 缺陷和没验证的

- 手机和微信都没有测。显卡帧率是 Radeon 780M 的结果，手机车数上限是推算。
- 128 打开要约 55 秒，主要是街区划分，放在客户端的话要拆到 Worker 或者预计算。
- 128 默认缩放下地图左右两个角在竖屏视口外，图标也被裁掉。
- 128 的地铁挤在西北角，公共服务盲区 82%；这两项验收检查查不出来，是看地铁视图和公共服务视图才看到的。
- 128 的城区路网过载 173 段，容量是临时值。
- 坡上只支持直路。默认城市绕开了转弯和路口，玩家自己画到坡上时要靠规则禁止，或者地形整平。
- 车流拥挤时环岛出口段偶尔有两辆车叠在一起，第 9 轮没有复查。
- 苜蓿叶和喇叭形未完成，第一版不交付。
- 半边菱形只有向北的匝道，南向只在两头进出。
- 车身在 8 个方向之间旋转时弯道上会变形。
- `verify.js`、`slopecheck.js`、`rampcheck.js`、`partition.js` 的尺寸写死，128 要改常量才跑得到；`preview.js` 还按 64。
- 探针目录在根目录 lint 下有 362 个错误（`no-undef` 150、`max-depth` 86、`complexity` 49、`max-params` 45、函数长度 29），探针用完就扔，没有处理。
- 影子方向全天不变。容量、费率、造价、补偿都是临时值。
- 第二套风格和压缩纹理没有做。
- `out/` 里 `r6-`、`r7-` 开头的截图是旧版本的。
