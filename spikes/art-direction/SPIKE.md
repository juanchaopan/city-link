# 探针：美术和界面方向

## 问题

低多边形玩具城能不能用代码做完全部素材？地块、物业、道路负担、公共服务、昼夜和风格包这些规则，能不能落到同一套数据和素材结构上？四级道路、立交、高架快速路、公共交通和动态车流能不能在这套结构上跑起来？地图放大到 128×128 要付出什么代价？

## 时间盒

八轮。第 1 到 3 轮定风格和配色，第 4、5 轮按用户新规则重做，第 6 轮修路面、重做街区划分、加道路体系和模块拼装实验，第 7 轮修切法打分、切坡两端、大三角的楼，第 8 轮做路口规划、立交线形、默认城市高架、统一遮挡、交通视图、公共服务、地铁公交和征收，并量 128×128。

## 不管的事

音效、全部素材、数值平衡、铁路、机场、海港、完整的线路编辑。

## 怎么运行

```
pnpm install --ignore-workspace
node scripts/verify.js        # 纯计算的验收检查，不通过时退出码是 1
node scripts/rampcheck.js     # 匝道坡度和立交圈内用地，不开浏览器
node scripts/slopecheck.js    # 切坡路基的像素检查，不开浏览器
node scripts/lotcheck.js      # 大三角物业的占地检查，不开浏览器
node scripts/partition.js     # 街区划分的前后对比
node scripts/preview.js lots|modules|tee|diamond|viaduct|center  # 软件光栅的形体预览，不开浏览器
node scripts/gen.js           # 烘三套调色的图集；node scripts/gen.js sunny 只烘一套
node scripts/budget.js        # 推算全部素材，要先有 sunny、dusk、dayOnly 三套烘焙结果
node scripts/occlusion.js 600 # 遮挡顺序验收，要先有 out/atlas-sunny.json
node scripts/ixcheck.js       # 丁字和菱形，出 r8-ix-tee、r8-ix-diamond、r8-ramp-merge、r8-ramp-cars
CITY=1 node scripts/ixcheck.js ix-city-report  # 默认城市里的立交和高架
node scripts/junctions.js     # 路口验收，出 r8-junction-sheet、r8-slope
node scripts/deckcheck.js     # 路面细线，出 r8-deck-zoom
node scripts/roadcheck.js     # 路面渲染遮罩验收
node scripts/lanes.js         # 只查高架和立交的车道
node scripts/sheets.js        # 成品样张，r8-viaduct-city、r8-occlusion、r8-public、r8-metro、r8-stations、r8-traffic
node --max-old-space-size=900 scripts/big.js   # 128×128 的生成和存档测量
pnpm serve                    # http://localhost:4180/
```

`SEAM=1 node scripts/shots.js` 跑露底和网格线检查，`FPS=1 node scripts/shots.js` 测帧率，加 `SOFT=1` 用软件渲染。`BIG=1 node scripts/gen.js sunny` 把 128 用到的精灵烘进图集，然后 `BIG=1 FPS=1 node scripts/shots.js` 量 128 的帧率，量完要重烘回 64 的图集。

`web/play.html` 的参数：`scene=interchange` 四级道路场景，`view=traffic|coverage|metro` 三种视图，`cars=300` 车辆上限（0 关闭），`full=1` 视野里一直保持满额的车，`t=22` 时间，`icons=0` 不画公共服务图标，`stress=3` 每个物业画 3 遍。

这台机器物理内存 15GB。开浏览器的步骤一次跑一项，每项单独记峰值，见下面的内存一节。

## 路面

路面用距离场在片元里画，一格的精灵会盖到邻格，所以拼接靠三条规则：

1. 全图分三层画：所有人行道、所有路缘、所有车道。后画的盖先画的，人行道不可能出现在车道上。
2. 裁剪按整条路做，不按线段做。
3. 路口圆角来自各方向沿直线延长后的平滑并集，对向的两个方向算一条直线。

路口垫片和邻格直路在两张精灵上，半透明的边叠不满时下层会透上来，看起来是一条细线。两张精灵多盖 0.03 格（`PAD_OVERLAP`）后叠满。

切坡的做法：台地四周是连续直坡；连续坡段的路面按整段匀速升降；挡墙和填方沿整段连续，填方等宽；切线为 0 的一头是坡段端点，挡墙高度、填方宽度和落差在这一格里平滑收到 0。

## 路口

斑马线两端接人行道，灯杆立在路缘外，停车线按车身长度算。相邻路口共用一格时斑马线不进另一个路口。五向以上做环岛。

信号灯八个方向各一张灯杆，灯面只有朝相机的 3 个方向各一张，背面不亮。灯杆立在进口右侧，悬臂伸到车道上方。这 11 张精灵的总面积约 3000 像素，比旧的 2 张多 9 张。

## 路面细线

`scripts/deckcheck.js` 用专门的配色烘焙：人行道和路缘白色，标线和路面同色，路面上剩下的任何颜色都是漏出来的。离路面边 0.035 格以内不查，亮度差上限 2（0 到 255）。查 12 个验收样例和默认城市 62 种路口，共 1200 万个采样点。

| 版本     | 组合 | 脏像素 | 最大亮度差 |
| -------- | ---- | ------ | ---------- |
| 没有多盖 | 68   | 4554   | 37         |
| 当前     | 74   | 1895   | 2 点几     |

这项按写明的阈值不通过：23 种组合各有几个到一百多个像素比上限高不到 1。放大 8 倍看 `out/r8-deck-zoom.png` 看不出线。五向以上是环岛，环岛区不查。

## 高架快速路

默认城市有一条高架快速路：从高速的快速路头爬上去，贴着一条南北街穿过城区，东侧一对匝道落到短街，再落回地面收成四车道接进横街的信号路口。快速路分地面和高架两种形态，同等级、同运力，造价系数地面 2、高架 6（每格，相对地面四车道，临时值）。形态只影响造价和画法。

主线占一列格子，路格里不立桥墩。西侧紧贴南北街放不下南向匝道，所以南向只在两头进出。主线在城里的地面段很短。样张 `out/r8-viaduct-city.png` 有全景、上下匝道、跨路口、引道过渡和落地，白天和夜里各一排。

## 遮挡

## 交通分配

住宅是起点，商业和工业是终点，起点的出行量按终点容量除以距离平方分配，沿行程时间最短的路走。快路单位时间短，所以长距离的出行自己绕到快路，上下快路要经过匝道。地图边上的三个出入口也是起点，出行量是全城终点容量的 25%。

| ------ | -------------- | ------------------ | ---- | -------- |
| 普通路 | 900            | 1                  | 527  | 0.56     |
| 四车道 | 1800           | 0.8                | 71   | 0.44     |
| 快速路 | 3000           | 0.35               | 3    | 0.12     |
| 高速   | 3600           | 0.3                | 105  | 0.08     |
| 匝道   | 1500           | 0.7                | 8    | 0.15     |

出行量 4306.5 全部分配，走不到 0，过载路段 0。

交通视图路面按负荷染色，宽度就是路面宽度，箭头沿方向流动，流速表示拥堵；点一个物业才显示门到路的箭头和它的车走的路。样张 `out/r8-traffic.png`。全城 1513 个箭头，帧率见帧率一节。

## 公共服务

每种服务有专用色，饱和度比分区颜色高，普通物业不用，`verify.js` 核对色差。图标牌在建筑上空，全图时放大到认得出，放大时不跟着放大。样张 `out/r8-public.png`。默认缩放下市中心的图标有重叠。用地分散时住宅盲区 34%，全集中时 87%。

风格包约定：换风格时公共服务的专用色和 `si-` 图标牌不换，别的物业不能用这些颜色。

## 地铁和公交

地铁 3 条线，1 个环，不分叉，2 个换乘站，1 处穿过不设站。隧道最小转弯半径 2 格，实测最紧 2.0 格。线路图和实际走线是同一条线，折线放不下圆弧时记下来提示玩家。地面 9 个站厅，各占一格，放在路边，入口朝人行道。样张 `out/r8-metro.png`、`out/r8-stations.png`。

公交站 138 个，在 64 个路格的人行道上，不占地块。公交经过站台时停在格子中央，停够时间再走，后面的车等。

## 征收

地铁站、公共用地、新修的路落到已有建筑上走同一个流程：先显示拆几栋、影响多少人、付多少钱，确认后才生效；居民一个游戏日内陆续搬走，楼拆除后再建。连体物业是一个地块，压到一格整块处理。费用每人 12、每格 40，临时值。默认城市的样例：拆 1 栋，影响 16 人，352；半天后还剩 8 人，一天后可以开工。

## 土地模型和街区划分

每格被两条对角线分成 4 个原子，每个面积正好 0.25。所有地块都是原子的并集，容量 = 原子数 × 分区等级费率，全部是整数运算。

街区划分在 `web/sim/partition.js`。规格表里有的完整形状并且贴普通道路，就整块成为一个物业；否则沿 0°、45°、90° 的格线递归切分。打分权重在 `web/sim/partition-weights.js`。建筑不贴普通道路就不长；切剩的边角是绿地。

怎么看这些数字：

- 显卡一列是 `requestAnimationFrame` 的速率，不是显卡画完一帧的实测时间，只能看相对差别。
- 车流现在是主要开销。游戏视角从无车的 333 掉到 300 辆的 109、600 辆的 57，多出来的主要是每帧把车插进静态序列和重新组装精灵。这台桌面 CPU 上排序就要 4 到 14 毫秒，手机上按 3 到 4 倍算，600 辆到不了 30 帧，要么降车数，要么把排序放到隔帧做。
- 软件渲染卡在像素填充上，游戏视角 0 到 600 辆几乎不变。它在 600 辆的用例里实际只有约 490 辆在屏幕里。
- 这些都不是手机数字。中端手机竖屏 30 帧的目标要在真机上量，这一轮没有量。

牵动的文档，按需要改动的方向列出，没有决定：

- ADR-0001：地形规格按 64×64、4 层比较过，128 要重新比较素材量和冷启动时间。
- ADR-0003：客户端按 64×64 选型，默认视野精灵数变成 4.3 倍，图集大 41%，全图缩小的帧率明显下降。
- ADR-0009：边界口偏移 8 到 21 或 43 到 55、对边错开 14 格都是按 64 定的，1920 座城的探针结论要重跑。
- 世界地图（REQ-011）：8×8 个位置不变，每个位置的城市面积变成 4 倍，边界要对齐的长度变成 2 倍。
- 存档：约 5.5 倍。
- REQ-027：街区划分 33 秒。放在云函数里跑要算进计费时长和超时，放在客户端要算进手机上的等待时间。
