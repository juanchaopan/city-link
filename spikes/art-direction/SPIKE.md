# 探针：美术和界面方向

## 问题

低多边形玩具城能不能用代码做完全部素材？地块、物业、道路负担、公共服务、昼夜、风格包和节日这些规则，能不能落到同一套数据和素材结构上？四级道路、立交和动态车流能不能在这套结构上跑起来？

## 时间盒

第 1 到 3 轮定风格和配色，第 4、5 轮按用户新规则重做，第 6 轮修路面、重做街区划分、加道路体系和模块拼装实验，第 7 轮修切法打分、切坡两端、大三角的楼，并把高速和城市路网连起来。

## 不管的事

音效、全部素材、数值平衡、公交、铁路、机场、海港、完整的线路编辑。

## 怎么运行

```
pnpm install --ignore-workspace
node scripts/verify.js      # 纯计算的验收检查，不需要显卡，不通过时退出码是 1
node scripts/slopecheck.js  # 切坡路基的像素检查，不开浏览器
node scripts/lotcheck.js    # 大三角物业的占地检查，不开浏览器
node scripts/partition.js   # 街区划分的修复前后对比
node scripts/preview.js lots|modules|tee|center  # 软件光栅的形体预览，不开浏览器
pnpm gen                    # 生成图集、风格包清单和节日包，写到 out/
node scripts/budget.js      # 推算全部素材的数量和大小
node scripts/roadcheck.js   # 路面渲染遮罩验收，输出 out/r6-road-sheet.png
node scripts/lanes.js       # 只查高架和立交
node scripts/modules.js     # 模块拼装样张
pnpm shots                  # 生成截图
pnpm serve                  # http://localhost:4180/
```

`SEAM=1 node scripts/shots.js` 跑露底和网格线检查，`FPS=1 node scripts/shots.js` 测帧率，加 `SOFT=1` 用软件渲染。

`web/play.html` 的参数：`scene=interchange` 四级道路场景，`linked=1` 和邻城打通，`cars=300` 车辆上限（0 关闭），`t=22` 时间，`stress=3` 让每个物业画 3 遍，用来量满城模块拼装的开销。

## 路面

路面用距离场在片元里画，一格的精灵会盖到邻格，所以拼接靠三条规则：

1. 全图分三层画：所有人行道、所有路缘、所有车道。后画的盖先画的，人行道不可能出现在车道上。
2. 裁剪按整条路做，不按线段做。
3. 路口圆角来自各方向沿直线延长后的平滑并集，对向的两个方向算一条直线。

用户报告的错误的根因：

| 现象                   | 根因                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------- |
| 弯道上白色弧线横穿车道 | 裁剪按线段做，贝塞尔折线中间的线段不裁，圆头越过格子边界，画在相邻格的车道上                 |
| 人行道尖角插进车道     | 每格一张精灵，后画的格子把人行道盖在先画格子的车道上                                         |
| 地图边缘的圆头         | 同一处根因：断头路的起点没有裁剪，线段按圆头收尾。断头路现在平切                             |
| 切坡路基像鼓包         | 地形是一层坡一层平，路面跟着地形走，挡墙填方只出现在坡格；邻格的地形用当前格的角外推也接不上 |
| 切坡挡墙两端竖直截断   | 挡墙带着整段的高度走到坡段的头，端点那一格没有收口                                           |

切坡的做法：台地四周是连续直坡；连续坡段的路面按整段匀速升降；挡墙和填方沿整段连续，填方等宽，地形按坡面线性外推；切线为 0 的一头是坡段端点，挡墙高度、填方宽度和落差在这一格里平滑收到 0。

## 土地模型和街区划分

每格被两条对角线分成 4 个原子，每个面积正好 0.25。所有地块都是原子的并集，容量 = 原子数 × 分区等级费率，全部是整数运算。

街区划分在 `web/sim/partition.js`。规格表里有的完整形状并且贴普通道路，就整块成为一个物业；否则沿 0°、45°、90° 的格线递归切分。一刀下去至少有一边是完整规格，地比最大规格还大时中线附近的切法也算。不贴路或没有规格的块不能成为物业，只能进兜底。打分权重在 `web/sim/partition-weights.js`：块大 0.5、切得少 0.2、顺斜边 0.15、规整 0.1、沿街均匀 0.05。

被斜路切过的方正街区有 5 块，第一名都不含斜向条带，块数不超过 4。斜边最长的那块切成大三角 4.5、矩形 6、大三角 2，3 块。

建筑不贴普通道路就不长；切剩的边角是绿地，只有小品（花坛、长椅、水池、雕塑、石景、亭子），没有容量和出入口。

## 大三角物业

楼形就是地块的形状，容量由规格决定，外观不改变容量。

| 分区 | 变体 0                                                                          | 变体 1                 |
| ---- | ------------------------------------------------------------------------------- | ---------------------- |
| 住宅 | 三翼连体围院子，沿斜边一翼加高；低密度且直角边不小于 4 格时是平行斜边的连排小楼 | 三翼连体，直角一角起塔 |
| 商业 | 占满地块的裙房，沿街一圈底商，高密度时裙房上站塔楼                              | 三翼围停车院           |
| 工业 | 占满地块的厂房，锯齿天窗                                                        | 三翼围堆场             |

直角边小于 3 格的地块留不出院子，用整块退台的楼形。模块拼装的 Q3 底座也占满三角地块，楼身站在内切圆上，露出来的屋面是花池。

## 路网数据结构

四级道路（`ROAD_SPEC`）：

| 等级                  | 车道 | 建筑能否接 | 路网里的位置                                            |
| --------------------- | ---- | ---------- | ------------------------------------------------------- |
| 双向两车道 `road`     | 2    | 能         | 格子的 `road` 方向位                                    |
| 双向四车道 `arterial` | 4    | 能         | 格子的 `arterial` 方向位，是 `road` 的子集              |
| 快速路 `express`      | 4    | 不能       | 高架是 `lanes` 和 `ev-` 精灵，地面段用 `highway` 方向位 |
| 高速 `highway`        | 6    | 不能       | 格子的 `highway` 方向位                                 |
| 匝道 `ramp`           | 1    | 不能       | `lanes`                                                 |

地面路网是 `Map<格子, {road, highway, arterial}>`，每个方向一位。高架和匝道是 `lanes`：每条一串 `[x, y, h]`，h 是层数；`fromCell`、`toCell` 接地面格，`exits`、`merge` 接主线。两头都在地面的匝道同时是路网图里的一条边（`links`），路段负担也算到它。

相交规则（`intersectionRule`）：同级普通路是信号路口；快速路和四车道是菱形；高速和快速路穿过是苜蓿叶，到头是喇叭形；高速和四车道到头是丁字形；其余不能直接相接。匝道只接高速、快速路和四车道，菱形立交的短街也是四车道。

| 立交   | 占地            | 匝道 | 素材             |
| ------ | --------------- | ---- | ---------------- |
| 菱形   | 9 × 15，135 格  | 4    | 1 张，加普通路面 |
| 苜蓿叶 | 17 × 17，289 格 | 8    | 1 张，加普通路面 |
| 喇叭形 | 17 × 15，255 格 | 4    | 1 张，加普通路面 |
| 丁字形 | 17 × 11，187 格 | 4    | 1 张，加普通路面 |

大地图上高速在城北 5 行，南北向的四车道主干伸到丁字立交，默认场景里就能看到；小地图放不下立交，高速只从城边经过。右转的两条匝道贴地，左转的两条各绕半个喇叭、在高架上跨过高速。匝道落地段最陡 1.13 层/格，比样张的高架坡 0.57 层/格陡一倍。

高架 5 张（平段和 4 段坡）。样张 `scene=interchange` 有三种快速路立交各一处（菱形两处）、一段高架、四车道接两车道的过渡。立交和高架是物体层的物体，和建筑一起排序：202 个物体违规 0，只按中心排序 10 处错误。物业不进立交占地（0 个原子），出入口接快速路 0。

`scripts/lanes.js` 的遮罩检查：第 6 轮主线、三种立交和高架下方的地面路共 1.9 万个采样点，断开 0。普通城市里的丁字立交已经加进这个检查，但还没有跑过。

## 车流和红绿灯

`web/vehicles.js` 是纯视觉层：只读路段负载比，不写任何东西，结算不知道它的存在。路口有信号灯，车红灯停、绿灯走、在路口转弯、走匝道。车只在屏幕内生成，出了屏幕回收，路段负载越高该段车越多，总数不超过 `cars`。地面的车画在物体层下面，高架上的车画在物体层上面。夜里有车灯和路面光斑。

匝道的端点压在格子边界上，车上下匝道时位置是连续的。车从匝道下到路网时按车尾朝向确定从哪一边进格子，所以断头格也接得住。

默认视角下实际车数 48 到 166 辆，达不到 300 的上限，因为样张负荷不高。

## 模块拼装实验

一栋楼由底座、楼身、屋顶三张精灵叠成，楼身一层正好 16 像素，模块之间不错位。2×2 和直角边 3 格的大三角各有 8 种组合，楼型有板楼、塔楼、L 形、双塔、退台、圆楼六种，也放进了城市（11 栋）。

发现的问题：

- 模块分开烘焙，楼身投不到底座上，没有接触阴影，比整张烘焙平一些。
- 圆楼没有窗户，夜里全黑。
- 楼身和屋顶不分方向，所以大三角的 4 个方向底座要各烘焙一份。

## 素材推算

第 6 轮的结果，第 7 轮没有重算。大三角的楼面比之前多，平均面积和 PNG 压缩率会变。按每规格每分区 7 种外观计算：

| 方案     | 张数 | PNG    | 纹理内存 | 64×64 物业精灵 |
| -------- | ---- | ------ | -------- | -------------- |
| 整张烘焙 | 1469 | 22.8MB | 286MB    | 400            |
| 模块拼装 | 1046 | 11.4MB | 144MB    | 1000           |

推荐模块拼装做中高密度的楼，低密度住宅、工厂和公共服务继续整张烘焙。楼身的配色按运行时染色计算，这一点没有实测。

## 风格包

清单 `out/style-standard.json`，`formatVersion` 是 2：

```json
{
  "formatVersion": 2,
  "id": "standard",
  "name": "标准",
  "tileWidth": 128,
  "atlases": [{ "image": "atlas-sunny.png", "frames": "atlas-sunny.json" }],
  "specs": ["B-r1-1x1-a-0", "Q-c2-3-1-0", "S-hospital-3x3"],
  "parts": ["Mp-2x2-0-shops", "Mb-tower-11-1", "Mr-crown"],
  "combos": {
    "2x2": [{ "podium": "shops", "body": "slab", "roof": "plant", "floors": 6, "tone": 0 }]
  },
  "festivalOverrides": {},
  "fallback": null
}
```

地块生成器只输出规格名，不知道风格。`specs` 是整张烘焙的规格，`parts` 是模块，`combos` 是同一规格的多种外观。外观不影响面积、容量和结算。节日层只认占地规格，不认外观，所以两种做法都能叠加。

回退：风格包缺失用标准风格，不改存档；某个规格缺失用标准风格同规格的图；两边都没有时留空地块。

## 节日包

清单 `out/festival-national-day-pack.json`，日期按国家时区判断，不写存档，到期自动恢复。

- 只装饰关键位置：公共服务、广场和市中心的高层商业。
- 每种占地规格一张叠加层：最靠近相机的一条边两端各一根灯笼杆，中间一条横幅。不用国旗和国徽。
- 样张 21 张、36KB。
- 叠加层在载入时画进主图集预留的区域，同一张纹理，绘制顺序紧跟建筑。

## 昼夜

白天图集加调色加亮窗层，关键帧连续过渡。地表下垫一张同色的底，背景和桌面随时间变暗，缩小全图时不再透出网格。

## 缺陷和没验证的

第 7 轮可用物理内存只有 1.0 到 1.5GB，不到开浏览器要求的 6GB，下面这些都没有跑：

- 图集没有重新烘焙。`out/atlas-*` 还是第 6 轮的，里面没有 `ix-tee` 和新路网、新大三角的精灵，`play.html` 的 64×64 场景要先跑 `pnpm gen` 才能打开。
- `roadcheck`、`lanes`、`shots`、`SEAM`、`FPS`、`FPS` 加 `SOFT`、`modules` 都没有跑。切坡、大三角和立交都没有看过真实烘焙的画面，只看过 `out/r7-*-preview.png` 的软件光栅预览。
- `out/r6-*.png` 全是第 6 轮的旧画面，`out/r6-road-sheet.png`、`out/r6-ix-*.png` 的立交中心还有修复前的碎片。
- 帧率没有 300、600 辆车、夜间车灯和满城模块拼装的数字。`out/fps-report.json` 是第 5 轮的旧数据。
- 第 6 轮的露底检查只跑了垫底的版本。
- 车上下丁字立交只读过代码，没有实际跑过。

其余缺陷：

- 斜向条带在这座城里一块也没有，斜路沿街几乎全靠大三角。
- 大三角的斜边沿着屏幕竖向时墙面正好和视线平行，这一面看不见立面，只看得见屋顶和另两面。
- 丁字立交的左转匝道落地段偏陡。
- 街区划分 64×64 要 9 到 25 秒，上线要放到后台分批做，或者换更快的实现。
