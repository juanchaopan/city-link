# 探针：美术和界面方向

## 问题

低多边形玩具城能不能用代码做完全部素材？地块、物业、道路负担、公共服务、昼夜、风格包和节日这些规则，能不能落到同一套数据和素材结构上？

## 时间盒

第 1 到 3 轮定风格和配色，第 4、5 轮按用户新规则重做。五轮已用完。

## 不管的事

动画、音效、全部素材、数值平衡、公交、铁路、机场、海港、完整的线路编辑。

## 怎么运行

```
pnpm install --ignore-workspace
node scripts/verify.js   # 纯计算的验收检查，不需要显卡
pnpm gen                 # 生成图集、风格包清单和节日包，写到 out/
node scripts/budget.js   # 推算全部素材的数量和大小
pnpm shots               # 生成截图
pnpm serve               # http://localhost:4180/
```

`SEAM=1 node scripts/shots.js` 跑拼缝检查，`FPS=1 node scripts/shots.js` 测帧率，加 `SOFT=1` 用软件渲染。

## 结构

| 目录 | 内容 |
|---|---|
| `web/sim/` | 纯逻辑，不依赖图形库：路网几何、地块生成器、公共服务选址、道路负担、遮挡顺序、地铁、风格包解析 |
| `web/kit/` | 素材生成器：three.js 建模和烘焙、距离场路面、标准风格的建筑 |
| `web/world.js`、`web/play.js` | Pixi 拼城和可操作的样张 |

## 土地模型

每格被两条对角线分成 4 个原子，每个面积正好 0.25。所有地块都是原子的并集，面积是 0.25 的整数倍。容量 = 原子数 × 分区等级费率，全部是整数运算。

地块的生成顺序体现"形状完整优先"：三角形空地整块成为一个物业 → 斜路两侧的斜向带 → 直角地块 → 连片农田 → 公共服务 → 公共用地余下的公园广场 → 小三角收边。

一个地块是一个物业，只有一个出入口、一份容量。楼、停车场和绿化画在同一张精灵里。

## 昼夜方案

| 方案 | 包体 | 软件渲染 P50 | 备注 |
|---|---|---|---|
| 白天图集加调色加亮窗层 | 5.83MB，亮窗比白天图集多 0.28MB | 25 帧 | 关键帧连续过渡；影子方向不变 |
| 两套图集 | 5.55 + 6.95 = 12.5MB | 16 帧 | 精灵翻倍，混合时最差 26 帧（硬件） |

推荐白天图集加调色加亮窗层。亮窗帧和建筑在同一张纹理上，紧跟建筑绘制，窗户不会透过前面的楼。

帧率：Radeon 780M 上全部被刷新率封顶在约 164 帧，所以比较用软件渲染（SwiftShader，像素比 1.5）。都不代表真机。

## 素材推算

| 方案 | 张数 | PNG | 纹理内存 | 备注 |
|---|---|---|---|---|
| 完整组合：规格 × 朝向 × 分区 × 3 等级 × 3 变体 | 1350 | 25.3MB | 253MB | 超过 20MB 规划 |
| 裁剪组合：2 等级 × 2 变体 | 855 | 13.7MB | 137MB | 包体够，内存要靠按需载入 |
| 模块拼装 | 879 | 3.9MB | 41MB | 推算，没做；64×64 多约 1.08 万个精灵 |

推荐裁剪组合整张烘焙，按城市用到的规格分页载入，并用压缩纹理。实际 64×64 样张用了 342 张，图集 4096×2552。模块拼装会丢掉整张烘焙的接触阴影，也会让精灵数翻好几倍，不推荐。

放大发虚：现在到缩放约 0.5 都清楚。把最大缩放限制在 0.6 不花钱；素材全翻倍要 PNG 约 3 倍、内存 4 倍，不推荐。

工时：烘焙 855 张约 4 分钟。第 4、5 轮写代码和看图约 2 小时，共 5458 行。还要新写铁路、车站、机场、港口、互通口等约 20 到 30 种模型，加上两轮人工看图，推算 5 到 8 个工作日。这是推算。

## 风格包

清单 `out/style-standard.json`：

```json
{
  "formatVersion": 1,
  "id": "standard",
  "name": "标准",
  "tileWidth": 128,
  "atlases": [{ "image": "atlas-sunny.png", "frames": "atlas-sunny.json" }],
  "specs": ["B-r1-1x1-a-0", "Q-c2-3-1-0", "S-hospital-3x3"],
  "festivalOverrides": {},
  "fallback": null
}
```

地块生成器只输出规格名，不知道风格。风格只决定规格名对应哪张图。

新增一套风格：

1. 按规格名渲染建筑、亮窗层（名字加 `~g`），规格列表可以只是标准风格的子集。
2. 写清单：id、名称、图集文件、提供的规格、可选的节日覆盖。
3. 把图集和清单放进素材目录，不改代码。

裁剪组合下一套风格约 470 张建筑，约 10MB。地表和道路不用重做。

回退：风格包缺失用标准风格，不改存档；某个规格缺失用标准风格同规格的图；两边都没有时留空地块。

## 节日包

清单 `out/festival-national-day-pack.json`，日期按国家时区判断，不写存档，到期自动恢复。

- 每种占地规格一张叠加层，含灯笼、彩旗串和红绸，不用国旗和国徽。
- 样张 20 张、125KB，图集高 183 像素；全部 33 种规格推算约 200KB。
- 叠加层在载入时画进主图集预留的区域，同一张纹理，绘制顺序紧跟建筑。
- 查找顺序：风格专属层 → 通用层 → 无装饰。

## 缺陷和没验证的

- 切坡路基能连续上台地，但挡墙矮，且因为两层坡之间有平台，分成两段。
- 斜向地块很少，64×64 只有 3 块，因为大三角优先占了地。
- 小三角收边还有 157 块，一排小店看着重复。
- 出入口只在交通视图和数据里，地面上没有画车行道。
- 圆塔的窗户夜里不亮。路灯没做。
- 影子方向全天不变。
- 公共服务半径、容量费率、路段容量都是临时值。
- 互通口没做，高速和普通路是平交。
- 国家和时区只在节日清单里留了字段，夜间玩法差异没做。
- 跨多张纹理没有验证：样张是一张 4096×2552。
- 没有在微信、iPhone 或安卓上跑过。
- 没有测压缩纹理。
- 第二套风格没有做，回退逻辑只用假数据测过。
