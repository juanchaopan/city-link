# 探针：美术和界面方向

## 问题

低多边形玩具城能不能用代码做完全部素材？地块、物业、道路负担、公共服务、昼夜和风格包这些规则，能不能落到同一套数据和素材结构上？四级道路、立交、高架快速路、公共交通和动态车流能不能在这套结构上跑起来？地图放大到 128×128 要付出什么代价？

## 时间盒

十轮。第 1 到 3 轮定风格和配色，第 4、5 轮按用户新规则重做，第 6 轮修路面、重做街区划分、加道路体系和模块拼装实验，第 7 轮修切法打分、切坡两端、大三角的楼，第 8 轮做路口规划、立交线形、默认城市高架、统一遮挡、交通视图、公共服务、地铁公交和征收，第 9 轮把默认地图定为 128×128，按这个尺寸收掉遮挡、路面、车道和性能问题，做路口规则的穷举验收和间距试验，第 10 轮按用户实开的截图修匝道口的排序成环、匝道脚的挡墙、环岛出口、分岔口溢出，并把路口改成现实的左转规则：两车道让行、四车道专用道。

## 不管的事

音效、全部素材、数值平衡、铁路、机场、海港、完整的线路编辑。

## 怎么运行

```
pnpm install --ignore-workspace
node scripts/verify.js        # 纯计算的验收检查，不通过时退出码是 1
node scripts/rampcheck.js     # 匝道坡度、贴地段的挡墙归属和立交圈内用地，不开浏览器
node scripts/slopecheck.js    # 切坡路基的像素检查，不开浏览器
node scripts/lotcheck.js      # 大三角物业的占地检查，不开浏览器
node scripts/partition.js     # 街区划分的前后对比
node scripts/replan.js 128    # 改一条路之后的增量重算，不开浏览器
node scripts/preview.js lots|modules|tee|diamond|viaduct|center  # 软件光栅的形体预览，不开浏览器
node scripts/gen.js           # 烘三套调色的图集，含 32、64、128 用到的全部精灵；node scripts/gen.js sunny 只烘一套
node scripts/budget.js        # 推算全部素材，要先有 sunny、dusk、dayOnly 三套烘焙结果
node scripts/occlusion.js 300 128  # 遮挡顺序验收，要先有 out/atlas-sunny.json；每帧排序成环的次数也要是 0
node scripts/rampcars.js      # 匝道和高架上车身叠在一起，不开浏览器
node scripts/screencheck.js   # 手机竖屏真实画面：公共服务图标、地铁线粗细、桥面切车
node scripts/ixcheck.js       # 丁字和菱形，出 r8-ix-tee、r8-ix-diamond、r8-ramp-merge、r8-ramp-cars
CITY=1 node scripts/ixcheck.js ix-city-report  # 默认城市里的立交和高架
node scripts/junctions.js     # 路口验收，128 全图，出 r8-junction-sheet、r8-slope
node scripts/shapes.js        # 路口穷举验收和间距试验，出 r9-junction-shapes、r9-spacing
node scripts/deckcheck.js     # 路面细线，出 r8-deck-zoom
node scripts/markcheck.js     # 停车线以内只有斑马线，查路口样例、穷举场景和 128 全图
node scripts/roadcheck.js     # 路面渲染遮罩验收，128 全图按 64 格见方分块
node scripts/lanes.js         # 只查高架和立交的车道
node scripts/sheets.js        # 成品样张，默认 128，SIZE=64 出 64 的
node --max-old-space-size=900 scripts/big.js   # 64 和 128 的生成和存档测量
pnpm serve                    # http://localhost:4180/
```

`verify.js`、`slopecheck.js`、`rampcheck.js`、`partition.js` 的地图尺寸写死在文件头上，默认 64（`verify.js` 是 32 和 64）。下面 128 的结果是把这个常量换成 128 跑的。

`scripts/shapes.js` 可以只跑 `shapes`、`spacing`、`sheets` 里的一步，`scripts/screencheck.js` 可以只跑 `views` 或 `cars`。这两个脚本都认 `REPLACE="文件@原文@替换"`：在页面加载时改一处源码，换行隔开多处，证明检查能失败、试不同的合并间距都用它。`shapes.js` 还认 `LIMIT=60`（只跑前 60 个场景）和 `REPORT=报告名`。

`SEAM=1 node scripts/shots.js` 跑露底和网格线检查，`FPS=1 node scripts/shots.js` 测帧率，加 `SOFT=1` 用软件渲染。`gen.js` 的输出不要接 `head`：管道一关进程就停，图集只写到一半，管道的退出码还是 0。根目录 `pnpm format` 会把 `out/` 里的 JSON 也格式化。

`web/play.html` 的参数：`n=128` 地图边长（默认 128），`scene=interchange` 四级道路场景，`view=traffic|coverage|metro` 三种视图，`cars=300` 车辆上限（0 关闭），`full=1` 视野里一直保持满额的车，`t=22` 时间，`icons=0` 不画公共服务图标，`stress=3` 每个物业画 3 遍。不写 `zoom` 时整张地图放进视口。`window.trafficStats()` 里的 `cycles` 是这一帧排序成环的次数。

这台机器物理内存 15GB。开浏览器的步骤一次跑一项，开之前看可用内存不低于 3GB。

## 路面

路面用距离场在片元里画，一格的精灵会盖到邻格，所以拼接靠三条规则：

1. 全图分三层画：所有人行道、所有路缘、所有车道。后画的盖先画的，人行道不可能出现在车道上。
2. 裁剪按整条路做，不按线段做。
3. 路口圆角只在小于 180° 的夹角里有：腿按角度排好，相邻两条腿的扇区里做平滑并集。直通一侧和路口背面的大扇区没有圆角，路缘就是路本身的边。延长线到邻格中心为止，长到 1.5 格会伸到没有路的地方。

路口垫片和邻格直路在两张精灵上，半透明的边叠不满时下层会透上来，看起来是一条细线。两张精灵多盖 0.03 格（`PAD_OVERLAP`）后叠满。

实心像素必须不透明。烘焙累加几十次光照，半浮点把小权重加到 2 时舍掉将近 1%，累加出来的 alpha 只有 253，颜色除以 alpha 后还亮 3 级。所以 alpha 不累加，取最后一次渲染的覆盖率。

地台贴地的矮边朝相机的 45° 斜边不画：它背光，屏幕上是一条笔直的水平深线，见 `web/kit/builder.js`。

车道线和中心线在停车线外缘结束，停车线以内只有斑马线，见 `web/sim/blanks.js`。路面精灵按估出来的退让距离画线，和真实的斑马线、停车线对不上，大路口和斜路口里中心线会穿过停车线和斑马线伸进路口。所以每条腿从路口一侧到停车线外缘铺一段路面色的底：信号路口从路口中心铺起，环岛从环路外缘铺起；底比车行道两边各窄 0.012 格，不盖到路缘。底有 1、0.5、0.25 格三种长度（`xb-种类-朝向-长度序号`，24 张），按长到短拼满这一段。全城的底先画完，再画斑马线和停车线。环岛入口不设分隔岛：尾端会压在斑马线上，像一根白色尖箭头。

`node scripts/markcheck.js` 在真实烘焙的遮罩上查：每条腿从路口一侧到停车线内缘、车行道以内，除去斑马线带和停车线，不能有标线色的像素；路面标记也不能画到离开车行道 0.02 格以外的地方。15 类路口样例、564 个穷举场景和 128 全图共 3924 条腿，标线像素 0、画到路外 0。不铺底的画法报 58817 个标线像素、1818 条腿，其中 128 全图 2064 个、716 条腿。

切坡的做法：台地四周是连续直坡；连续坡段的路面按整段匀速升降；挡墙和填方沿整段连续，填方等宽；切线为 0 的一头是坡段端点，挡墙高度、填方宽度和落差在这一格里平滑收到 0。

坡上只放得下直路。转弯和路口的路面贴着这一格的地形，精灵超出格子的部分和邻格错开；默认城市的布局绕开了这种情况，上台地的路在台地顶上的平地收尾。

树林的影子烘在水平面上，放到坡上或坡边会悬空离开树脚，看起来是树下一团深色模糊，这些格子用不带影子的树林（名字带 `bare`）。

## 路口

规则：

1. 3、4 条路用红绿灯，含 45° 夹角的不规则路口；5 到 8 条用环岛。
2. 每个路口生成进出连线表（`web/sim/junctions.js`）：每条进路能去哪、走哪条线，线就是车走的车道中线（`web/sim/lanes.js`）。靠右行驶。45° 的弯里车道和路面中线保持车道偏移的距离；急弯的交点贴着起点时用三次曲线，先开到路口中间再绕回来。
3. 车道：两车道的路一个方向只有一条车道，所有走向排一条队。四车道的路靠中线的内侧车道是左转专用道：左转的线从内侧车道进路口，直行和右转走外侧车道；车在停车线前一格就选好走向，左转的横移到内侧车道，在路口里也单独排队，直行的从旁边过。
4. 相位：相对的路一组，不成对的路单独一组。每组先有一相放行全部走向，左转在这一相里让行：两车道没有左转专用道，也就没有左转专用灯，左转车和直行车一起放行，左转车开进路口，在和对向直行相交之前停下来等空档，对向的车还在路口里、或者在停车线前亮着绿灯就等，没有了才过。同一相里相交的线，直行优先于右转、右转优先于左转，连线表记下让谁、在线上哪一点之前让。四车道的左转有专用道才另设保护左转相，排在放行相后面，保护相里的线互不相交。4 条两车道路的路口 2 相，带四车道的 3 到 4 相，大路口最多 8 相。
5. 让行时的队：单车道进口上，比让行的左转车晚到停车线的车不管直行还是右转都在停车线后等，不跟进路口、不穿过它；左转车过了让行点，后车才跟进。有让行的路口全红加上让行车从让行点通过的那一段。
6. 灯按车道分：每条腿的灯杆上外侧车道一面灯，有左转专用道的进口在悬臂上靠杆的一侧再挂一面左转灯，各按自己车道的相位染色，灯亮绿就是这条车道的排头能走。灯杆在每条进路右侧人行道上，停车线之前，灯头迎着来车。
7. 每条路一条斑马线，垂直穿路，两头接人行道，放在路缘转弯结束之后，45° 夹角退到两路真正分开处，这时灯杆落在尖角岛上。停车线紧贴斑马线之前。
8. 两个路口相邻或只隔 1 格时算一个大路口：共用信号，连接段不放灯、不画斑马线，车不停在连接段里。隔 2 格及以上各自独立。
9. 放行要出口放得下：数到下一个路口停车线的整段路，减去路上的车和已经放行、正开过去的车，前一格绿灯放进停车格的车也算，路段中间生成的车也算。环岛的车进环前也看这一条，出口排满时在让行线前等，环上不会被堵死。

信号灯八个方向各一张灯杆，灯面只有朝相机的 3 个方向各一张，背面不亮。左转灯用同一张灯面精灵，没有另烘。这 11 张精灵的总面积约 3000 像素。

## 间距试验

| 斜路路口   | .36/.31，30 秒 | .23/.54，15 秒 | .49/.76，15 秒 | 2、5 辆            |

秒数是信号周期。两车道路口只剩 2 相（合并的大路口 3 相），周期从上一轮的 25 到 83 秒缩到 14 到 30 秒，车速是上一轮的 1.3 到 2.5 倍，代价是左转车在路口里等空档，每个场景 3 到 33 个让行样本。环岛接路口隔 1 格时出口只排得下 3 辆公交，车进环前看出口放不放得下，不看的话 40 辆公交把环堵死，25 个样本停在环里。

规则的来历：上一轮在隔 1、2、3 格上合并和不合并都跑过。隔 1 格不合并时排不下公交，斜路车速只有 .06，几乎不动，所以合并；隔 2 格放行数整段路以后，不合并同样 0 错误，车速是合并的 1 到 3 倍；隔 3 格合并只会把周期拉长。放行不数整段路时不合并的错误是：隔 1 格 8 到 154 个，隔 2 格 0 到 51 个，隔 3 格 0 到 17 个。

建议规划道路时提示路口至少隔 2 格。这些都是 24×24 小图的压测数字，不是真实城市负荷。

`scripts/lanes.js` 交付范围全部通过。贴地的车道从桥下穿过时，屏幕上那一点读到的是桥的路肩，检查再读一次不画结构的遮罩，那里是车道就不算压路肩。把采样推到路肩外的变异版本 tee 这一行报 50 个，检查还抓得到真问题。

车在坡上的倾斜有两种做法。烘焙要给每个方向再烘几档坡度，8 个方向 4 种颜色加公交的 40 张要翻几倍。运行时旋转不加精灵，车头跟路面走向连续变化，换精灵时不跳，选的是这种。代价是偏离 8 个方向最远时车身会变形，弯道上看得出，见 `out/r8-ramp-cars.png`，要改善就加到 16 个方向。

两条匝道共用一段路面时算一支队（`web/sim/sharedlanes.js`）：丁字立交两条匝道在地面路口前并成一条路、也从同一路口出发走一段才分开，匝道并入和驶出主线时也贴着主线走一段。这几段上的车按到共用端点的距离排队，后车跟前车，不管前车在哪条 lane 上；上匝道和生成车时也看另一条 lane 上的车。只看自己那条 lane 时，丁字立交左侧匝道的排队车两两叠在一起。`scripts/rampcars.js` 在两处立交视野里取 105 帧，按车身矩形查平面重叠：旧车流 292 对（丁字 263、高架分岔和并入口 29），现在 0（丁字 7670 个车样本、高架 9452 个）。

匝道落到地面路上的那一格只有一条路从这里出去，进来的方向没有路，车道偏移按出去的那条路算；之前按两车道算，车从匝道开到格子里横跳 0.14 格。

## 高架快速路

默认城市有一条高架快速路：从高速的快速路头爬上去，贴着一条南北街穿过城区，东侧一对匝道落到短街，再落回地面收成四车道接进横街的信号路口。快速路分地面和高架两种形态，同等级、同运力，造价系数地面 2、高架 6（每格，相对地面四车道，临时值）。形态只影响造价和画法。

## 遮挡

全城一份绘制序列：地面、路面先画，然后车、灯杆、建筑、桥墩、桥面混排，桥面上的车在桥面后面。公交按车身占地算。规则写在 `web/sim/order.js`。每帧把视野和周边一圈的静态物体和车一起做拓扑排序，静态物体之间的边只算一次，见 `web/sim/drawlist.js`。

车和桥面按画出来的样子比：桥面用画出来的范围，车身连同往下挪了 3 像素的精灵一起算；两个凸多边形重叠就是桥面先画，不重叠再按视线比。只看三条视线时，压住桥面一角的车会漏掉，被前面那块多画的路面切掉大半个车身。车只可能压着比自己低不到 0.15 层的桥面：接缝前坡上的车比邻块的最低点略低，这是多画的那一截和车身前探的范围在最陡的坡上能差出的高度；贴地开过匝道脚旁边的车比匝道块低得多，它在匝道块身后，按视线排。

排序成环是用户截图里两个毛病的根因。主线上的车贴着并口开过时压在匝道块的边上，匝道块要先画；车又在前面那块主线身后，车先画；并口的匝道块按规则排在主线后面画，三样东西成环，放行谁都画错：放行车，车被匝道的路面切掉一边（截图里匝道口只剩一条薄片的车）；放行匝道块，主线的路缘线画在并口上，有车经过时出现，车走了又消失（截图里时有时无的封闭线）。现在三条规则去掉环：车身前面、顶不比车底高的桥面不和车连边，这种桥面连护栏在内都在车身下方，屏幕上碰不到车身；桥上的车在桥墩身后时桥墩先画，不然桥墩、车、车脚下的桥面也成环；桥面的顶按画出来的范围算，按占地算会把多画那一截的高度算进去，高估小半层。排序仍然成环时沿前驱找到真正的环，先放行只被别的车挡着的车，没有再放行环上最靠后的；成环的次数每帧报告，检查要求是 0。

## 环岛

环岛 5×5，车逆时针绕行，进环让行，见 `web/sim/roundabout.js`。上一轮遗留的出口叠车有两个根因：出环的车进外面那一格时方向反了，车跳到格子另一头再开回环里，和进环的车叠在一起；驶向环岛的车看的是格子的队，环岛的车按进口分队，队名不一样，进环的车看不到前车，叠在环的进口上。现在出环按出口臂的反方向进格，两个环岛门对门时下一格直接按环岛的队算，环上刚切进切出的车车身也算在前车里，进环前出口要放得下。`scripts/rampcars.js` 的判法搬到 20 个环岛上各取 210 帧，车身重叠从 1 万到 69 万对降到 0（上一轮每个环岛 10 万到 69 万对，都是进口上叠着的车）；只剩两处路口格里对向转弯的车各碰一次，不在环岛上。

## 公共服务

每种服务有专用色，饱和度比分区颜色高，普通物业不用，`verify.js` 核对色差，最近 56，下限 45。数量上限按地图面积放大。样张 `out/r8-public.png`。

## 征收

地铁站、公共用地、新修的路落到已有建筑上走同一个流程：先显示拆几栋、影响多少人、付多少钱，确认后才生效；居民一个游戏日内陆续搬走，楼拆除后再建。连体物业是一个地块，压到一格整块处理。费用每人 12、每格 40，临时值。

## 土地模型和街区划分

每格被两条对角线分成 4 个原子，每个面积正好 0.25。所有地块都是原子的并集，容量 = 原子数 × 分区等级费率，全部是整数运算。

街区划分在 `web/sim/partition.js`。规格表里有的完整形状并且贴普通道路，就整块成为一个物业；否则沿 0°、45°、90° 的格线递归切分。打分权重在 `web/sim/partition-weights.js`。建筑不贴普通道路就不长；切剩的边角是绿地。

划分按街区缓存，键是原子加每原子沿街边长。`planPartition()` 返回任务，`run(budgetMs)` 每批解几个街区就停。`node scripts/replan.js 128`：

| 项目                 | 街区 | 重算 | 总时间  | 单块最坏 |
| -------------------- | ---- | ---- | ------- | -------- |
| 冷启动               | 368  | 368  | 37.2 秒 | 274 毫秒 |
| 横穿全城画一条新路后 | 381  | 46   | 4.3 秒  | 102 毫秒 |
| 同一条路，不用缓存   | 381  | 381  | 35.6 秒 | 270 毫秒 |

8 毫秒预算分 27 批，结果和不用缓存完全一致。单块是递归动态规划，不能在块内中断，最坏一块卡一帧，要真不阻塞得放 Web Worker，或者调小 `BLOCK_BUDGET`、`MAX_REGION` 换质量。

## 帧率

设备：AMD Ryzen 9 7940HS 笔记本，物理内存 15GB，测试时可用约 3GB，机器上没有别的重任务。视口 390×844。每项测 5 秒。车数是回报的实际数。游戏视角是缩放 0.42，视野内约 550 个静态物体。显卡是 Radeon 780M 集成显卡，D3D11，3 倍像素比，关垂直同步和帧率上限。

| 用例                | 车数 | p50 | p95 | 最差 | 每帧排序 |
| ------------------- | ---- | --- | --- | ---- | -------- |
| 128 鸟瞰全图        | 0    | 238 | 164 | 133  | 0        |
| 128 半图缩小        | 0    | 227 | 127 | 83   | 0        |
| 128 游戏视角        | 300  | 87  | 63  | 51   | 6 毫秒   |
| 128 游戏视角        | 150  | 135 | 104 | 79   | 3.5 毫秒 |
| 128 游戏视角        | 100  | 164 | 128 | 65   | 5 毫秒   |
| 128 夜间车灯        | 300  | 86  | 66  | 50   | 5.5 毫秒 |
| 128 交通视图        | 0    | 175 | 145 | 111  | 0        |
| 64 游戏视角（对比） | 300  | 78  | 58  | 39   | 6.2 毫秒 |

软件渲染（SwiftShader，1.5 倍像素比，只靠 CPU）上一轮的数字：游戏视角 100 到 300 辆都是 16 帧，卡在像素填充上，这一轮没有重测。

怎么看这些数字：

- 显卡一列是 `requestAnimationFrame` 的速率，只能看相对差别。这一轮可用内存比上一轮少 1GB，300 辆比上一轮低 7 帧，100 辆高 11 帧，在同一台机器的波动范围里。
- 地图大小影响不大：128 和 64 游戏视角差 9 帧，每帧只处理视野和周边一圈。
- 车是主要开销，其中排序 300 辆约 6 毫秒。让行和排队的判断在车流里，300 辆满额时每帧多扫几次全部车，没有单独量。
- 这些都不是手机数字。第一版的目标是中端手机竖屏 30 帧，这一轮没有真机。

手机默认车数上限建议 100，高端机放到 150，300 只留给桌面调试。这是推算：手机 CPU 按这台的 3 到 4 倍慢算，300 辆一帧 32 到 42 毫秒，超过 30 帧的 33 毫秒；150 辆 21 到 28 毫秒；100 辆 18 到 24 毫秒，还要留余量给图形。上限要在真机上再定一次。

牵动的文档，按需要改动的方向列出，没有决定：

- ADR-0001：地形规格按 64×64、4 层比较过，128 要重新比较素材量和冷启动时间。
- ADR-0003：客户端按 64×64 选型，默认视野精灵数变成 4.3 倍，图集变大。
- ADR-0009：边界口偏移 8 到 21 或 43 到 55、对边错开 14 格都是按 64 定的，1920 座城的探针结论要重跑。
- 世界地图（REQ-011）：8×8 个位置不变，每个位置的城市面积变成 4 倍，边界要对齐的长度变成 2 倍。
- 存档：约 5.5 倍。
- REQ-027：街区划分 35 秒左右。放在云函数里跑要算进计费时长和超时，放在客户端要算进手机上的等待时间，桌面浏览器打开已经要 36 秒。

## 模块拼装实验

一栋楼由底座、楼身、屋顶三张精灵叠成，楼身一层正好 16 像素。2×2 和直角边 3 格的大三角各有 8 种组合，样张 `out/r6-modules.png`。推荐模块拼装做中高密度的楼，低密度住宅、工厂和公共服务继续整张烘焙。模块分开烘焙，楼身投不到底座上，比整张烘焙平一些。圆楼没有窗户，夜里全黑。

## 风格包

清单 `out/style-standard.json`，`formatVersion` 是 2。地块生成器只输出规格名，不知道风格。`specs` 是整张烘焙的规格，`parts` 是模块，`combos` 是同一规格的多种外观。外观不影响面积、容量和结算。

回退：风格包缺失用标准风格，不改存档；某个规格缺失用标准风格同规格的图；两边都没有时留空地块。

## 实开 play.html?n=128

无头 Chrome 里打开，手机竖屏视口 390×844、2 倍像素比，一次约 36 秒。城市、交通、公共服务覆盖、地铁四个视图都在真实默认缩放（0.021，整张地图放进竖屏）下截图放大看过；真实鼠标拖动、滚轮放大、时间滑块拖到 22 点入夜都正常，全程控制台除 404 外没有错误。近景放大看过市中心路口、环岛、高架、丁字立交和台地坡上的树林：斑马线中间没有线头，环岛入口没有白色尖三角，桥上没有被切的车，匝道排队车不叠，坡上树下没有深色影子。第 10 轮在缩放 1.2 到 6 下连拍看过高架并口、半边菱形两头、丁字立交匝道脚和一个两车道路口：并口的路缘线每帧一样，匝道脚的挡墙连到地面，左转车在路口中间等对向车、后面的车在停车线后等。`full=1` 时 300 辆车集中在视野里，路口前排很长的队，这是满额压测的样子。

## 缺陷和没验证的

- 手机和微信都没有测。显卡帧率是 Radeon 780M 的结果，手机车数上限是推算。
- 大路口相位多，最多 8 相。相位表没有把互不相交的相合并，还有压缩的余地。
- 四车道的左转专用道只在停车线前一格开始横移；停车线落在路口格里、前一格又是别的路口的格子时，左转车横移不了，还在外侧车道上排队。默认城市和 564 个穷举场景里没有碰到。
- 让行的左转车只在对向的车在路口里、或者在停车线前亮绿灯时等；对向的车在让行车过冲突点的那一瞬间才放行时，两辆车在路口里挨得很近，检查里没有量这种车距。
- 高架分岔口的主线在模拟里只有一条车道，出口匝道排满时要驶出的车不上匝道、接着往前开，排到主线最外侧车道上的样子没有做。
- 丁字立交两条匝道在脚下并成一条路的那一段，两块路面在平面上重叠，一条匝道的挡墙穿过另一条的路面画到地面，两条路面的层序交界处墙露出一截台阶，放大 6 倍能看到。
- 坡上和坡边的树林不带影子，树和地面的接触感比平地上弱；要贴坡的影子得按坡向另烘几组。
- 环岛附近两处路口格里对向转弯的车各碰到一次（210 帧里），不在环岛上，没有查。
- 128 打开要约 36 秒，主要是街区划分，放在客户端的话要拆到 Worker 或者预计算。
- 128 的城区路网过载 173 段，容量是临时值。
- 坡上只支持直路。默认城市绕开了转弯和路口，玩家自己画到坡上时要靠规则禁止，或者地形整平。
- 苜蓿叶和喇叭形未完成，第一版不交付。
- 半边菱形只有向北的匝道，南向只在两头进出。
- 车身在 8 个方向之间旋转时弯道上会变形。
- `verify.js`、`slopecheck.js`、`rampcheck.js`、`partition.js` 的尺寸写死，128 要改常量才跑得到；`preview.js` 还按 64。
- 探针目录在根目录 lint 下有 404 个错误（主要是 `no-undef`、`max-depth`、`complexity`、`max-params`、函数长度），探针用完就扔，没有处理。
- 影子方向全天不变。容量、费率、造价、补偿都是临时值。
- 第二套风格和压缩纹理没有做。页面默认只用 sunny，dusk 和 dayOnly 跟着 sunny 一起烘。
- `out/` 里 `r6-`、`r7-` 开头的截图是旧版本的。
