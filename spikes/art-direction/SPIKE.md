# 探针：美术和界面方向

## 问题

低多边形玩具城能不能用代码做完全部素材？地块、物业、道路负担、公共服务、昼夜和风格包这些规则，能不能落到同一套数据和素材结构上？四级道路、立交、高架快速路、公共交通和动态车流能不能在这套结构上跑起来？地图放大到 128×128 要付出什么代价？

## 时间盒

九轮。第 1 到 3 轮定风格和配色，第 4、5 轮按用户新规则重做，第 6 轮修路面、重做街区划分、加道路体系和模块拼装实验，第 7 轮修切法打分、切坡两端、大三角的楼，第 8 轮做路口规划、立交线形、默认城市高架、统一遮挡、交通视图、公共服务、地铁公交和征收，第 9 轮把默认地图定为 128×128，按这个尺寸收掉遮挡、路面、车道和性能问题，做路口规则的穷举验收和间距试验，最后按真实默认缩放复查视图、桥面切车和匝道叠车。

## 不管的事

音效、全部素材、数值平衡、铁路、机场、海港、完整的线路编辑。

## 怎么运行

```
pnpm install --ignore-workspace
node scripts/verify.js        # 纯计算的验收检查，不通过时退出码是 1
node scripts/rampcheck.js     # 匝道坡度和立交圈内用地，不开浏览器
node scripts/slopecheck.js    # 切坡路基的像素检查，不开浏览器
node scripts/lotcheck.js      # 大三角物业的占地检查，不开浏览器
node scripts/partition.js     # 街区划分的前后对比
node scripts/replan.js 128    # 改一条路之后的增量重算，不开浏览器
node scripts/preview.js lots|modules|tee|diamond|viaduct|center  # 软件光栅的形体预览，不开浏览器
node scripts/gen.js           # 烘三套调色的图集，含 32、64、128 用到的全部精灵；node scripts/gen.js sunny 只烘一套
node scripts/budget.js        # 推算全部素材，要先有 sunny、dusk、dayOnly 三套烘焙结果
node scripts/occlusion.js 300 128  # 遮挡顺序验收，要先有 out/atlas-sunny.json
node scripts/rampcars.js      # 匝道和高架上车身叠在一起，不开浏览器
node scripts/screencheck.js   # 手机竖屏真实画面：公共服务图标、地铁线粗细、桥面切车
node scripts/ixcheck.js       # 丁字和菱形，出 r8-ix-tee、r8-ix-diamond、r8-ramp-merge、r8-ramp-cars
CITY=1 node scripts/ixcheck.js ix-city-report  # 默认城市里的立交和高架
node scripts/junctions.js     # 路口验收，128 全图，出 r8-junction-sheet、r8-slope
node scripts/shapes.js        # 路口穷举验收和间距试验，出 r9-junction-shapes、r9-spacing
node scripts/deckcheck.js     # 路面细线，出 r8-deck-zoom
node scripts/roadcheck.js     # 路面渲染遮罩验收，128 全图按 64 格见方分块
node scripts/lanes.js         # 只查高架和立交的车道
node scripts/sheets.js        # 成品样张，默认 128，SIZE=64 出 64 的
node --max-old-space-size=900 scripts/big.js   # 64 和 128 的生成和存档测量
pnpm serve                    # http://localhost:4180/
```

`verify.js`、`slopecheck.js`、`rampcheck.js`、`partition.js` 的地图尺寸写死在文件头上，默认 64（`verify.js` 是 32 和 64）。下面 128 的结果是把这个常量换成 128 跑的。

`scripts/shapes.js` 可以只跑 `shapes`、`spacing`、`sheets` 里的一步，`scripts/screencheck.js` 可以只跑 `views` 或 `cars`。这两个脚本都认 `REPLACE="文件@原文@替换"`：在页面加载时改一处源码，换行隔开多处，证明检查能失败、试不同的合并间距都用它。

`SEAM=1 node scripts/shots.js` 跑露底和网格线检查，`FPS=1 node scripts/shots.js` 测帧率，加 `SOFT=1` 用软件渲染。`gen.js` 的输出不要接 `head`：管道一关进程就停，图集只写到一半，管道的退出码还是 0。根目录 `pnpm format` 会把 `out/` 里的 JSON 也格式化。

`web/play.html` 的参数：`n=128` 地图边长（默认 128），`scene=interchange` 四级道路场景，`view=traffic|coverage|metro` 三种视图，`cars=300` 车辆上限（0 关闭），`full=1` 视野里一直保持满额的车，`t=22` 时间，`icons=0` 不画公共服务图标，`stress=3` 每个物业画 3 遍。不写 `zoom` 时整张地图放进视口。

这台机器物理内存 15GB。开浏览器的步骤一次跑一项，开之前看可用内存不低于 3GB。

## 路面

路面用距离场在片元里画，一格的精灵会盖到邻格，所以拼接靠三条规则：

1. 全图分三层画：所有人行道、所有路缘、所有车道。后画的盖先画的，人行道不可能出现在车道上。
2. 裁剪按整条路做，不按线段做。
3. 路口圆角只在小于 180° 的夹角里有：腿按角度排好，相邻两条腿的扇区里做平滑并集。直通一侧和路口背面的大扇区没有圆角，路缘就是路本身的边。延长线到邻格中心为止，长到 1.5 格会伸到没有路的地方。

路口垫片和邻格直路在两张精灵上，半透明的边叠不满时下层会透上来，看起来是一条细线。两张精灵多盖 0.03 格（`PAD_OVERLAP`）后叠满。

实心像素必须不透明。烘焙累加几十次光照，半浮点把小权重加到 2 时舍掉将近 1%，累加出来的 alpha 只有 253，颜色除以 alpha 后还亮 3 级。所以 alpha 不累加，取最后一次渲染的覆盖率。

地台贴地的矮边朝相机的 45° 斜边不画：它背光，屏幕上是一条笔直的水平深线，见 `web/kit/builder.js`。

路面精灵的中心线和车道线不知道斑马线在哪里：路口格按估出来的退让距离开始画线，和实际放斑马线的位置对不上，斑马线退到隔壁的直路格时也挡不住，斑马线中间会出现一小截线，像个「+」。斑马线精灵先铺一层路面色的底，从内侧到停车线都盖住，标线在斑马线之前结束。环岛入口原来有宽 0.1 格的分隔岛，尾端压在斑马线上，看起来是一根白色尖箭头，去掉了。

切坡的做法：台地四周是连续直坡；连续坡段的路面按整段匀速升降；挡墙和填方沿整段连续，填方等宽；切线为 0 的一头是坡段端点，挡墙高度、填方宽度和落差在这一格里平滑收到 0。

坡上只放得下直路。转弯和路口的路面贴着这一格的地形，精灵超出格子的部分和邻格错开；默认城市的布局绕开了这种情况，上台地的路在台地顶上的平地收尾。

树林的影子烘在水平面上，放到坡上或坡边会悬空离开树脚，看起来是树下一团深色模糊，这些格子用不带影子的树林（名字带 `bare`）。

## 路口

规则：

1. 3、4 条路用红绿灯，含 45° 夹角的不规则路口；5 到 8 条用环岛。
2. 每个路口生成进出连线表（`web/sim/junctions.js`）：每条进路能去哪、走哪条线，线就是车走的车道中线（`web/sim/lanes.js`）。靠右行驶。45° 的弯里车道和路面中线保持车道偏移的距离；急弯的交点贴着起点时用三次曲线，先开到路口中间再绕回来。
3. 相对的路一组，不成对的路单独一组。同一相内车线不相交：一组里对向的左转穿过对面直行，这些线排到紧接着的下一相。4 条路的路口 4 到 6 相，3 条路的 3 相。灯杆在每条进路右侧人行道上，停车线之前，灯头迎着来车。
4. 每条路一条斑马线，垂直穿路，两头接人行道，放在路缘转弯结束之后，45° 夹角退到两路真正分开处，这时灯杆落在尖角岛上。停车线紧贴斑马线之前。全部灯杆都放得下，悬臂灯的退路没有用到，也没有实现；所有灯杆本来就带悬臂。
5. 两个路口相邻或只隔 1 格时算一个大路口：共用信号，连接段不放灯、不画斑马线，车不停在连接段里。隔 2 格及以上各自独立。
6. 放行要出口放得下：数到下一个路口停车线的整段路，减去路上的车和已经放行、正开过去的车，路段中间生成的车也算。

信号灯八个方向各一张灯杆，灯面只有朝相机的 3 个方向各一张，背面不亮。这 11 张精灵的总面积约 3000 像素。

`scripts/junctions.js` 在真实烘焙拼出来的遮罩上查 15 类路口和 128 全图，全部通过。按规则 5 只合并隔 1 格以后，128 全图的灯杆从 1350 根变成 1370 根：

## 间距试验

`node scripts/shapes.js spacing`。间隔是两个路口之间隔着几格路，环岛接路口从环岛 5×5 的边算。40 辆车挤在 24×24 的小图上，全公交和混合车流各一遍，这是压测。样张 `out/r9-spacing.png`。

按现行规则（只合并隔 1 格）重跑，全部间距错误 0、停在路口里的样本 0、车卡死 0。车速单位格每秒，公交/混合：

| 场景       | 隔 1（合并）   | 隔 2（不合并） | 隔 3（不合并） | 隔 2、3 能排的公交 |
| ---------- | -------------- | -------------- | -------------- | ------------------ |
| 十字接十字 | .23/.27，65 秒 | .54/.56，25 秒 | .54/.59，25 秒 | 4、6 辆            |
| 十字接丁字 | .33/.35，49 秒 | .47/.48，25 秒 | .46/.54，25 秒 | 4、6 辆            |
| 斜路路口   | .21/.21，83 秒 | .30/.25，33 秒 | .27/.29，33 秒 | 2、5 辆            |
| 环岛接路口 | .48/.48，33 秒 | .49/.46，33 秒 | .46/.47，33 秒 | 5、8 辆            |

秒数是信号周期。环岛不参加合并，隔 1 格也能排 3 辆公交。

规则的来历：上一轮在隔 1、2、3 格上合并和不合并都跑过。隔 1 格不合并时排不下公交，斜路车速只有 .06，几乎不动，所以合并；隔 2 格放行数整段路以后，不合并同样 0 错误，车速是合并（.18 到 .33）的 1 到 3 倍；隔 3 格合并只会把周期拉到 60 到 107 秒。放行不数整段路时不合并的错误是：隔 1 格 8 到 154 个，隔 2 格 0 到 51 个，隔 3 格 0 到 17 个。

建议规划道路时提示路口至少隔 2 格。这些都是 24×24 小图的压测数字，不是真实城市负荷。

`scripts/ixcheck.js` 查八项（同高相交、桥墩压路、转角超过 8°、侧面露缝、车开到路肩上、车道有洞、开口隔着路缘、车偏离车道中线），丁字、菱形和默认城市的半边菱形、快速路头、丁字全部是 0。默认城市高架主线 11 格：路格里的桥墩 0，净空不足 0，主线下面的物业 0。

立交切成小块，相邻两块在接缝处多画两个节点互相盖住。多画的部分不算占地：桥面之间的先后按占地排，算上它们，主线和匝道的几块就排成了环。车和桥面比较时用画出来的范围（`painted`）。主线和匝道可能只叠一角，排序看三条视线；主线节点 0.1 格一个，接缝只多画 0.2 格，节点半格一个时多画一格，主线的路肩盖到隔壁格的匝道上，菱形立交有 30 个压路肩的采样。

`scripts/lanes.js` 交付范围全部通过。贴地的车道从桥下穿过时，屏幕上那一点读到的是桥的路肩，检查再读一次不画结构的遮罩，那里是车道就不算压路肩。把采样推到路肩外的变异版本 tee 这一行报 50 个，检查还抓得到真问题。

车在坡上的倾斜有两种做法。烘焙要给每个方向再烘几档坡度，8 个方向 4 种颜色加公交的 40 张要翻几倍。运行时旋转不加精灵，车头跟路面走向连续变化，换精灵时不跳，选的是这种。代价是偏离 8 个方向最远时车身会变形，弯道上看得出，见 `out/r8-ramp-cars.png`，要改善就加到 16 个方向。

两条匝道共用一段路面时算一支队（`web/sim/sharedlanes.js`）：丁字立交两条匝道在地面路口前并成一条路、也从同一路口出发走一段才分开，匝道并入和驶出主线时也贴着主线走一段。这几段上的车按到共用端点的距离排队，后车跟前车，不管前车在哪条 lane 上；上匝道和生成车时也看另一条 lane 上的车。只看自己那条 lane 时，丁字立交左侧匝道的排队车两两叠在一起。`scripts/rampcars.js` 在两处立交视野里取 105 帧，按车身矩形查平面重叠：旧车流 292 对（丁字 263、高架分岔和并入口 29），现在 0。匝道上在动的车占比和以前一样（丁字 46%，高架 23%，都是满额压测）。

## 高架快速路

## 遮挡

全城一份绘制序列：地面、路面先画，然后车、灯杆、建筑、桥墩、桥面混排，桥面上的车在桥面后面。公交按车身占地算。规则写在 `web/sim/order.js`。每帧把视野和周边一圈的静态物体和车一起做拓扑排序，静态物体之间的边只算一次，见 `web/sim/drawlist.js`。

车和桥面按画出来的样子比：桥面用画出来的范围，车身连同往下挪了 3 像素的精灵一起算；两个凸多边形重叠就是桥面先画，不重叠再按视线比。只看三条视线时，压住桥面一角的车会漏掉，被前面那块多画的路面切掉大半个车身。排序成环时沿前驱找到真正的环，先放行只被别的车挡着的车，没有再放行环上最靠后的；放行全部没画物体里最靠后的一个，桥上的车不在环上也会被先放出去，画在自己脚下的桥面底下。

## 征收

地铁站、公共用地、新修的路落到已有建筑上走同一个流程：先显示拆几栋、影响多少人、付多少钱，确认后才生效；居民一个游戏日内陆续搬走，楼拆除后再建。连体物业是一个地块，压到一格整块处理。费用每人 12、每格 40，临时值。

## 土地模型和街区划分

每格被两条对角线分成 4 个原子，每个面积正好 0.25。所有地块都是原子的并集，容量 = 原子数 × 分区等级费率，全部是整数运算。

街区划分在 `web/sim/partition.js`。规格表里有的完整形状并且贴普通道路，就整块成为一个物业；否则沿 0°、45°、90° 的格线递归切分。打分权重在 `web/sim/partition-weights.js`。建筑不贴普通道路就不长；切剩的边角是绿地。

划分按街区缓存，键是原子加每原子沿街边长。`planPartition()` 返回任务，`run(budgetMs)` 每批解几个街区就停。`node scripts/replan.js 128`：

| 项目                 | 街区 | 重算 | 总时间  | 单块最坏 |
| -------------------- | ---- | ---- | ------- | -------- |
| 冷启动               | 368  | 368  | 37.2 秒 | 274 毫秒 |
| 横穿全城画一条新路后 | 381  | 46   | 4.3 秒  | 102 毫秒 |
| 同一条路，不用缓存   | 381  | 381  | 35.6 秒 | 270 毫秒 |

8 毫秒预算分 27 批，结果和不用缓存完全一致。单块是递归动态规划，不能在块内中断，最坏一块卡一帧，要真不阻塞得放 Web Worker，或者调小 `BLOCK_BUDGET`、`MAX_REGION` 换质量。

显卡是 Radeon 780M 集成显卡，D3D11，3 倍像素比，关垂直同步和帧率上限；软件是 SwiftShader，1.5 倍像素比，只靠 CPU。这组数字是在「成环只放行环上物体」那次修改之前测的，那次只改了成环时放行谁，一帧里成环只有几次，没有重测。

怎么看这些数字：

- 显卡一列是 `requestAnimationFrame` 的速率，只能看相对差别。同一台机器别的进程忙时 300 辆只有 63 帧，看比例不看绝对值。
- 地图大小影响不大：128 和 64 游戏视角差 4 帧，每帧只处理视野和周边一圈。
- 车是主要开销，其中排序 300 辆约 6.5 毫秒、150 辆 6 毫秒、100 辆 3.2 毫秒。
- 软件渲染卡在像素填充上，游戏视角 100 到 300 辆都是 16 帧，车数不是瓶颈。
- 这些都不是手机数字。第一版的目标是中端手机竖屏 30 帧，这一轮没有真机。

手机默认车数上限建议 100，高端机放到 150，300 只留给桌面调试。这是推算：手机 CPU 按这台的 3 到 4 倍慢算，300 辆一帧 32 到 42 毫秒，超过 30 帧的 33 毫秒；150 辆 21 到 28 毫秒；100 辆 18 到 24 毫秒，还要留余量给图形。上限要在真机上再定一次。

## 模块拼装实验

一栋楼由底座、楼身、屋顶三张精灵叠成，楼身一层正好 16 像素。2×2 和直角边 3 格的大三角各有 8 种组合，样张 `out/r6-modules.png`。推荐模块拼装做中高密度的楼，低密度住宅、工厂和公共服务继续整张烘焙。模块分开烘焙，楼身投不到底座上，比整张烘焙平一些。圆楼没有窗户，夜里全黑。

## 风格包

清单 `out/style-standard.json`，`formatVersion` 是 2。地块生成器只输出规格名，不知道风格。`specs` 是整张烘焙的规格，`parts` 是模块，`combos` 是同一规格的多种外观。外观不影响面积、容量和结算。

回退：风格包缺失用标准风格，不改存档；某个规格缺失用标准风格同规格的图；两边都没有时留空地块。

## 实开 play.html?n=128

无头 Chrome 里打开，手机竖屏视口 390×844、2 倍像素比，一次约 36 秒。城市、交通、公共服务覆盖、地铁四个视图都在真实默认缩放（0.021，整张地图放进竖屏）下截图放大看过；真实鼠标拖动、滚轮放大、时间滑块拖到 22 点入夜都正常，全程控制台除 404 外没有错误。近景放大看过市中心路口、环岛、高架、丁字立交和台地坡上的树林：斑马线中间没有线头，环岛入口没有白色尖三角，桥上没有被切的车，匝道排队车不叠，坡上树下没有深色影子。`full=1` 时 300 辆车集中在视野里，路口前排很长的队，这是满额压测的样子。

## 缺陷和没验证的

- 手机和微信都没有测。显卡帧率是 Radeon 780M 的结果，手机车数上限是推算。
- 保护左转相「绿灯但排头直行不动」：同一条进路只有一条车道，灯按进路显示，保护左转那一相这条进路的灯是绿的，排头要直行的车还在等，看起来像绿灯不走。探针不修，正式版要解决：加左转箭头灯或者左转车道，灯按车道显示。
- 大路口相位多，周期 49 到 83 秒，车速明显下降，见间距试验。相位表没有把互不相交的相合并，还有压缩的余地。
- 斑马线的路面色底只盖斑马线到停车线这一段。斑马线退到隔壁直路格时，内侧还会露出一两个像素的中心线断头，放大才看得见。
- 坡上和坡边的树林不带影子，树和地面的接触感比平地上弱；要贴坡的影子得按坡向另烘几组。
- 地铁视图默认缩放下两个换乘站离得近，第一个「换乘站」的字尾挨着第二个换乘站的圆圈。
- 环岛出口段偶尔有车叠在一起，第 9 轮没有查根因；匝道和高架上的叠车已经修掉，`rampcars.js` 只查这两处。
- 共用一段路面的匝道排成一支队以后，高架分岔口下游的匝道排满时，主线贴着分岔口的一小段车也跟着等（满额压测下 15 秒以上不动的采样从 0 变成 192 个），真实负荷下没有看。
- 128 打开要约 36 秒，主要是街区划分，放在客户端的话要拆到 Worker 或者预计算。
- 128 的城区路网过载 173 段，容量是临时值。
- 坡上只支持直路。默认城市绕开了转弯和路口，玩家自己画到坡上时要靠规则禁止，或者地形整平。
- 苜蓿叶和喇叭形未完成，第一版不交付。
- 半边菱形只有向北的匝道，南向只在两头进出。
- 车身在 8 个方向之间旋转时弯道上会变形。
- `verify.js`、`slopecheck.js`、`rampcheck.js`、`partition.js` 的尺寸写死，128 要改常量才跑得到；`preview.js` 还按 64。
- 探针目录在根目录 lint 下有几百个错误（主要是 `no-undef`、`max-depth`、`complexity`、`max-params`、函数长度），探针用完就扔，没有处理。
- 影子方向全天不变。容量、费率、造价、补偿都是临时值。
- 第二套风格和压缩纹理没有做。
- `out/` 里 `r6-`、`r7-` 开头的截图是旧版本的。
