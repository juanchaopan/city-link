# 探针：河网骨架是否可行（ADR-0009、Q-015）

这是探针代码，只用来回答问题，永远不合并进正式代码。

## 要回答的问题

城市群创建时先生成河网骨架，再在首次占用时按骨架生成地形，能否做到至少 70% 的位置有河、干流连通，同时保住可建面积和全部连接点？回归城市带着旧河道时怎么和骨架配合？

## 判据

前五条来自 ADR-0009 和本次指令，不放宽。"明显直角和回环""长直段"在 ADR 里没有数字，这里先定义再运行。R10 是第二轮看图后补上的，比原判据更严。

| 编号 | 判据 | 通过条件 |
|---|---|---|
| R1 | 硬失败 | 随机顺序占满 30 个城市群（1920 座城），无法生成的次数为 0 |
| R2 | 接缝 | 边界高度、水体全部相同，高差和水位违规为 0，独立检查 |
| R3 | 覆盖率 | 每个城市群至少 70% 的位置有河，按最终地形独立统计 |
| R4 | 干流连通 | 按最终地形，3×3 全水的通航格能把该群所有干流位置连起来 |
| R5 | 河流不断 | 所有河流边界口都和干流网 4 邻接连通 |
| R6 | 可建面积 | 每座城不低于 60% |
| R7 | 连接点 | 首笔贸易和全部连通失败都是 0 |
| R8 | 耗时 | 单次生成 P95 不超过 100 毫秒，64×64，Node 单线程 |
| R9 | 观感 | 回环为 0；明显直角低于每 100 格 0.5 个 |
| R10 | 长直段 | 每段河道的最长直段 P95 不超过 30 格 |

观感的算法：沿河道中心线取前后各 4 格的弦，夹角超过 70° 记一个明显直角；弧长相差 24 格以上而直线距离不到 7 格记一个回环；偏离弦不超过 1 格的连续河段记为直段。结果另外看整群 PNG。

## 三轮过程

| 轮次 | 做法 | 结果 | 发现 |
|---|---|---|---|
| 1 | 骨架树、边界口预先固定、格子路径加 Chaikin 平滑 | 13 座硬失败，直角 1.33/100 格 | 河流把中心围住；路径小折角很多 |
| 2 | 留一条河流不能穿过的新手走廊；滑动平均平滑；路点形成大弯；按观感挑路线 | R1 到 R9 全过，最长直段 63 格 | 有河段贯穿整座城 |
| 3 | 对边的两个口错开；中段叠加小幅蜿蜒；湖泊按可用空间定大小，只留和中心连通的部分；重试时缩小湖泊 | R1 到 R10 全过 | 中途发现两个缺陷，见下 |

第三轮修掉的缺陷：
- 湖泊粗糙度噪声的坐标超出网格，得到 NaN，湖泊变成正方形。这时的水体比例和可建面积都是错的。
- 湖泊被障碍切成碎片时，支流可能接到孤立的水面上，造成 2 个河口断开。

|---|---|---|
| R1 硬失败 | 0，没有一次重试 | 通过 |
| R2 接缝 | 高度、水体、高差、水位、范围违规都是 0 | 通过 |
| R3 覆盖率 | 每群 79.7%，最低 79.7% | 通过 |
| R4 干流连通 | 909 / 909 个干流位置连通 | 通过 |
| R5 河流不断 | 3000 个河口断开 0 个 | 通过 |
| R6 可建面积 | 平均 78.2%，P5 68.7%，最小 60.9% | 通过 |
| R7 连接点 | 首笔贸易失败 0，全部连通失败 0 | 通过 |
| R8 耗时 | P50 24.1，P95 75.2 毫秒，最大 1055 毫秒 | 通过，最大值原因未查 |
| R9 观感 | 回环 0；明显直角干流 0.12、支流 0.13/100 格 | 通过 |
| R10 长直段 | 干流 P95 25、最大 36；支流 P95 23、最大 29 | 通过 |

30 个样本里有 3 个城市群完全没有海岸，干流止于湖泊；每群干流位置 29 到 33 个，约 47%。

## 回归城市

做法：
1. 骨架给每个位置一个签名：四条边是否有河、干流还是支流。
2. 回归城市只放进签名相同、外边界类型相同、8 个相邻位置都没有地形的空位。
3. 骨架上这个位置四个边界口的偏移改成旧城市的偏移。四周都没有地形，所以改动不影响已生成的城市。
4. 开放城市群里没有这种空位时，新建城市群；创建骨架只要约 1 毫秒，可以换种子直到出现匹配。

样本：60 座城市放进新位置后占满整群，见 `out/returning.json`。

| 指标 | 结果 |
|---|---|
| 放置成功 | 59 / 60 |
| 接缝、高差、水位违规 | 0 |
| 干流连通 | 1788 / 1788 |
| 河口断开 | 0 / 5900 |
| 相邻城市生成失败 | 0 |
| 放进约三成已占用的开放城市群 | 1 座 |
| 放进新建城市群 | 58 座，平均换 31 个种子 |

没放成的 1 座签名是 `t-t-`，400 个种子内没有匹配位置。开放城市群里几乎找不到空位，因为 8 个相邻位置都要空着。结论是回归城市基本都进新建城市群，要接受这名玩家的邻居多为系统城市。签名少见时应该在创建骨架时直接锚定这个签名，这一步没有实现。

## 判断

ADR-0009 的方案可行，全部判据通过，可以从"提议"改为"已接受"。

建议参数：见 `params.js`。主要是干流位置 45%、有河位置 80%、干流 3 格、支流 1 格、路线离障碍 4 格、新手走廊半宽 3 格、河边低地 3 格、可建面积保底 60%、湖泊半径 8 到 12 格（按空间收缩）、边界口偏移 8 到 21 或 43 到 55、对边的口至少错开 14 格。

## 还没验证的事

- 回归城市的锚定骨架没有实现，少见签名可能放不下。
- 河流没有流向和上下游，也没有验证水运路径、通航运力和桥下通行。
- 过河连接点按探针旧规则验证：斜路只走角形坡。全坡八方向是超集，不会更难修通。
- 素材量没有估算：3 格河岸、汇流口、河口和码头都没算。
- 耗时最大值 1055 毫秒原因未查；云函数上的耗时没有测。
- 同一城市群按顺序生成只做了串行模拟，没有实现租约。
- 2.5D 画面下的河流和湖泊观感没有看过，只看了俯视图。
- 判据 R9、R10 的数字是这次探针自己定的，用户还没有确认。
