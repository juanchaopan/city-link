## REQ-001 新手引导和十分钟首笔贸易

- 优先级：MVP
- 状态：有效
- 来源：用户回答；引导内容为 AI 建议，用户默认
- 用户故事：作为新手市长，我想要被一步步带着修路、划区并卖出第一批商品，以便很快看到城市和贸易是怎么运转的。
- 验收标准：
  1. Given 新玩家第一次进入游戏，When 按引导完成操作，Then 十分钟内完成修路、划区、产出商品和首笔陆上贸易。
  2. Given 新玩家的相邻位置都是系统城市，When 进入首笔贸易步骤，Then 仍能与系统城市完成贸易。
  3. Given 新玩家中途退出，When 再次进入，Then 从未完成的引导步骤继续。
  4. Given 新城市的地形已经生成，When 引导开始，Then 引导使用中心平地和可修通的连接点完成流程。
- 业务规则：
  - 首笔贸易只使用道路、分区和跨城公路。
  - 公交、地铁、水电和公共服务不在首笔贸易流程中出现。
- 边界和异常：
  - 贸易服务不可用：引导保留在贸易步骤，并提示稍后再试，已建成的内容不受影响。
- 相关：REQ-003、REQ-004、REQ-007、REQ-012、REQ-013、REQ-014、REQ-033

## REQ-002 微信登录和云存档

- 优先级：MVP
- 状态：有效
- 来源：AI 建议，用户默认
- 用户故事：作为玩家，我想要用微信身份进入游戏并自动保存城市，以便换手机后还能继续玩。
- 验收标准：
  1. Given 玩家打开小游戏，When 完成微信身份确认，Then 无需额外注册就能进入自己的城市。
  2. Given 玩家在新设备打开小游戏，When 登录成功，Then 恢复云端最新存档。
  3. Given 同一账号同时在两台设备打开，When 后打开的设备连接成功，Then 先打开的设备提示已在其他设备登录并退出，不产生两份冲突存档。
- 业务规则：
  - 每个微信身份只有一座城市。
  - 游戏内昵称由玩家设置，不需要微信头像和微信昵称。
- 边界和异常：
  - 云存档失败：本地继续保留未上传的操作，联网后重试。
- 相关：REQ-022、REQ-024、REQ-025

## REQ-003 八方向道路规划

- 优先级：MVP
- 状态：有效
- 来源：用户回答；地形规则为 AI 建议，用户默认
- 用户故事：作为市长，我想要用手指在网格上修水平、垂直和 45° 斜向的道路，并顺着地形规划，以便做出符合自己想法的路网。
- 验收标准：
  1. Given 玩家打开修路工具，When 手指沿网格滑动，Then 预览并生成对齐网格的八方向道路。
  2. Given 两条道路相交，When 确认修建，Then 在相交处形成路口。
  3. Given 斜路旁出现锯齿边缘，When 道路完成，Then 这些边缘放置绿化或小型设施。
  4. Given 玩家资金不足，When 尝试修路，Then 拒绝超出资金的部分并提示所需资金。
  5. Given 路线经过不同高度层，When 预览道路，Then 自动生成坡道并显示造价。
  6. Given 路线跨过河流或湖泊，When 确认修建，Then 生成桥并按桥的价格计费。
- 业务规则：
  - 道路只走水平、垂直和 45° 共八个方向。
  - 分区和建筑仍然是方格。
  - 铁路和地铁使用同样的方向规则。
  - 道路造价随地形变化，具体规则见 REQ-034。
- 边界和异常：
  - 拆除道路导致建筑不连通：拆除前提示影响，确认后再执行。
  - 坡度超过道路允许的范围：不允许修建，并提示绕行。
- 相关：REQ-004、REQ-005、REQ-010、REQ-013、REQ-033、REQ-034

## REQ-004 住宅、商业、农业和工业分区

- 优先级：MVP
- 状态：有效
- 来源：用户回答；产业关系为 AI 建议，用户默认
- 用户故事：作为市长，我想要根据地形规划住宅、商业、农业和工业分区，以便让城市人口和产业逐步发展。
- 验收标准：
  1. Given 玩家选中分区工具，When 在连通道路的可建设地块划区，Then 区域被标记为对应分区。
  2. Given 分区具备道路连接，When 城市运转一段时间，Then 分区内逐步出现建筑并产生人口或产出。
  3. Given 分区没有道路连接，When 城市运转，Then 分区不发展，并提示缺少道路。
  4. Given 地块是水体或坡度过大，When 尝试划区，Then 拒绝这部分地块并提示原因。
- 业务规则：
  - 农业产出原料，工业加工出商品，商业和外贸消化商品，住宅提供人口；具体商品种类见 Q-011。
  - 建筑只能建在高度一致的地块上。
  - 分区产出和居民满意度受地形影响，具体规则见 REQ-034。
- 边界和异常：
  - 分区重叠：拒绝重叠的部分。
  - 拆除有建筑的分区：提示损失，确认后执行。
- 相关：REQ-003、REQ-006、REQ-014、REQ-033、REQ-034、Q-011

## REQ-005 道路流量和拥堵

- 优先级：MVP
- 状态：有效
- 来源：用户回答；模拟粒度为 AI 建议，用户默认
- 用户故事：作为市长，我想要看到每段道路的流量和拥堵，以便通过修路和调整布局解决问题。
- 验收标准：
  1. Given 城市有多段道路，When 打开交通视图，Then 每段道路用颜色显示流量和拥堵程度。
  2. Given 某段道路拥堵，When 玩家修建替代路线，Then 流量重新分配，这段道路的拥堵下降。
  3. Given 城市规模达到第一版上限，When 模拟运行，Then 不模拟单辆车，手机仍保持流畅。
- 业务规则：
  - 模拟算到每段道路的流量，不模拟单辆车。
  - 拥堵影响居民满意度和商品运输时间。
- 边界和异常：
  - 手机性能不足：可以降低更新频率，但不能改变经济结算结果。
- 相关：REQ-003、REQ-006、REQ-009、REQ-010、Q-005

## REQ-006 城市经济和恢复机制

- 优先级：MVP
- 状态：有效
- 来源：用户回答
- 用户故事：作为市长，我想要管理城市的收入和支出，出现亏损时也能通过调整恢复，以便不必担心城市被清空。
- 验收标准：
  1. Given 城市有税收和贸易收入，When 周期结算，Then 资金变化能在界面上查看。
  2. Given 资金不足，When 周期结算，Then 公共服务降级、居民满意度下降，但城市不破产。
  3. Given 城市处于资金不足状态，When 玩家调整规划或领取救济资金，Then 城市逐步恢复。
- 业务规则：
  - 城市不会破产，也不会被系统删除。
  - 资金是整数，只在游戏内使用，不能兑换现金。
  - 救济资金有领取频率限制，具体数值见 Q-006。
- 边界和异常：
  - 资金不足的城市有过境线路：继续通行，不影响邻居贸易。
- 相关：REQ-008、REQ-014、REQ-021、Q-006

## REQ-011 城市群和世界地图

- 优先级：MVP
- 状态：有效
- 来源：用户回答；布局和外边界为 AI 建议，用户默认
- 用户故事：作为玩家，我想要在城市群里拥有一个位置，以便和周围城市连接、一起发展。
- 验收标准：
  1. Given 新玩家进入，When 分配位置，Then 他的城市被放到一个开放城市群的空位，并显示城市群地图。
  2. Given 城市群有 64 个位置，When 查看世界地图，Then 按 8×8 方格显示所有位置及其状态，已生成的位置显示地形概貌。
  3. Given 开放的城市群全部没有空位，When 新玩家进入，Then 系统开放一个新城市群。
  4. Given 城市群创建，When 确定外边界，Then 四条外边各自是不可通行的远山或海岸。
- 业务规则：
  - 每个城市群 64 座城市，按 8×8 方格排列，每座城市最多 4 个陆上邻居。
  - 群内可以使用陆上和航空连接，群之间只能使用航空连接。
  - 空位包括系统城市的位置，以及满足替换条件的流失城市的位置。
  - 新玩家优先放在与真人城市相邻的空位。
  - 城市群外边界不生成连接点，第一版海岸不提供海运。
- 边界和异常：
  - 同时有多名玩家争一个空位：只有一人成功，其他人重新分配。
- 相关：REQ-012、REQ-013、REQ-016、REQ-017、REQ-020、REQ-033

## REQ-012 系统城市

- 优先级：MVP
- 状态：有效
- 来源：AI 建议，用户默认
- 用户故事：作为新手市长，我想要在真人很少的城市群里也有交易对象，以便不用等别人就能开始贸易。
- 验收标准：
  1. Given 城市群有空位，When 没有真人玩家占用，Then 由系统城市占位。
  2. Given 玩家与系统城市相邻，When 修好跨城公路，Then 可以按系统价格贸易。
  3. Given 贸易路线经过系统城市，When 路线计算，Then 使用系统城市预置的东西、南北向线路通过。
  4. Given 位置从未被玩家占用，When 相邻位置生成地形，Then 系统城市不提供地形，也不影响生成结果。
- 业务规则：
  - 系统城市只有预置的线路和贸易需求，没有地形，不模拟城市内部。
  - 新玩家进入时替换系统城市；位置第一次被玩家占用时生成地形。
  - 系统城市按同样费率收取过路费，这笔费用不归属任何玩家。
- 边界和异常：
  - 系统城市被替换：经过它的贸易按 REQ-020 处理。
- 相关：REQ-001、REQ-011、REQ-013、REQ-015、REQ-033

## REQ-013 公路和铁路陆上连接

- 优先级：MVP
- 状态：有效
- 来源：用户回答；地形规则为 AI 建议，用户默认
- 用户故事：作为市长，我想要用公路和铁路连接同一城市群的城市，以便通过陆路做贸易。
- 验收标准：
  1. Given 两座城市相邻，When 双方的公路或铁路都修到共同边界，Then 形成陆上连接。
  2. Given A 和 B 通过铁路相连，B 和 C 也通过铁路相连，When A 向 C 贸易，Then 货物可以穿过 B 到达 C。
  3. Given 公路形成同样的连接链，When 贸易时，Then 也可以通过 B 到达 C。
  4. Given 陆上连接被一方拆除，When 操作完成，Then 受影响的贸易按 REQ-014 的路线规则处理。
  5. Given 地形已生成，When 修建到共享边界，Then 每条共享边的连接点都能从城市内部修通。
- 业务规则：
  - 陆上连接只在同一城市群内有效。
  - 公路先解锁，铁路后解锁且运力更大。
  - 两座城市的边界连接点要对齐。
  - 公路和铁路使用和道路相同的坡道与桥规则。
- 边界和异常：
  - 邻居没有修到边界：显示待对方连接，等待对方修好或由系统城市自动接通。
- 相关：REQ-003、REQ-014、REQ-015、REQ-033、REQ-034

## REQ-014 连线后自动贸易

- 优先级：MVP
- 状态：有效
- 来源：用户回答；中断处理为 AI 建议，用户默认
- 用户故事：作为市长，我想要设定出口商品和配额后由系统自动交易，以便不用守着订单也能和其他城市做生意。
- 验收标准：
  1. Given 两座城市已连通且配额匹配，When 服务端结算，Then 货物按系统价格自动流动，资金和商品同时变化。
  2. Given 对方离线，When 服务端结算，Then 贸易按离线规则继续进行。
  3. Given 存在多条可用路线，When 系统选路，Then 选择运输时间和过路费综合成本最低的路线。
  4. Given 路线中断且有替代路线，When 系统重新选路，Then 贸易继续并通知受影响的城市。
  5. Given 路线中断且没有替代路线，When 结算，Then 贸易暂停并通知双方，途中的货物不丢失。
- 业务规则：
  - 玩家通过设定出口、进口的商品和配额表示同意交易，不需要逐笔确认。
  - 价格由系统决定，玩家不能议价。
  - 贸易连接的状态：未连通、运行中、暂停（断路、无货或配额用尽）、已关闭。
  - 途中货物的状态：运输中、已送达、已退回。
- 边界和异常：
  - 买方资金不足：只成交买得起的部分。
  - 卖方库存不足：只成交有库存的部分，其余继续等待。
- 相关：REQ-013、REQ-015、REQ-016、REQ-019、REQ-021、Q-006、Q-011

## REQ-015 过境和过路费

- 优先级：MVP
- 状态：有效
- 来源：用户回答
- 用户故事：作为途经城市的市长，我想要从穿过我城市的贸易中收到过路费，以便有动力修好线路。
- 验收标准：
  1. Given B 的线路连通了两侧城市，When A 和 C 的贸易经过 B，Then 自动通行，无需 B 确认。
  2. Given 贸易经过 B，When 结算，Then B 按系统费率收到过路费。
  3. Given B 的线路拥堵或运力不足，When 贸易通过，Then 运输时间变长。
- 业务规则：
  - 过路费率由系统决定，途经城市不能修改，也不能拒绝通行。
  - 途经城市可以拆除自己的线路，由此造成的中断按 REQ-014 处理。
  - 过路费计入途经城市的离线收益上限。
- 边界和异常：
  - 途经城市资金不足：不影响通行。
  - 途经城市流失：线路按最后状态保持，直到被替换。

  4. Given 相邻城市有河流到达共享边界，When 生成新地形，Then 河流在新城市继续，并流向另一条边界或汇入湖泊。
  5. Given 相邻城市已有建筑，When 生成新地形，Then 已有城市的地形和建筑都不变。
  6. Given 地形生成完成，When 检查结果，Then 中心平地、可建面积保底和全部连接点都满足要求。
  7. Given 同一城市群有两个位置同时被占用，When 生成地形，Then 按顺序生成，后生成的位置贴合先生成的位置。
- 业务规则：
  - 地形只生成一次，属于位置，不属于玩家；玩家不能重新随机，也不能修改地形。
  - 地形类型包括平地、山丘、河流、湖泊、森林和矿产；海岸出现在城市群外边界，地形有 3 到 4 层真实高度。
  - 相邻地块高度差不超过 1 层，不生成悬崖。
  - 河流和湖泊只在最低层。
  - 河流不沿共享边界长距离延伸。
  - 新地形参考 8 个相邻位置；四条共边用于贴合边界，四角用于保证角点一致。
  - 可建面积保底、地形比例和高度层数见 Q-012。
- 边界和异常：
  - 生成失败：不把玩家放进城市，重新生成或换一个空位；已占用的位置要释放。
  - 随机结果不满足保底：重新生成，不把不合格的地形交给玩家。
  - 河流从多个方向到达：汇合成一条河流或汇入湖泊，不能在城市内断开。
  - 城市位于城市群边缘：贴合对应的远山或海岸外边界。

## REQ-034 地形影响造价和产业

- 优先级：MVP
- 状态：有效
- 来源：用户回答；具体影响为 AI 建议，用户默认
- 用户故事：作为市长，我想要因地制宜地规划城市，以便不同地形能带来不同的优势和选择。
- 验收标准：
  1. Given 道路经过山丘，When 显示造价，Then 比平地更贵。
  2. Given 道路或铁路跨过河流或湖泊，When 显示造价，Then 需要修桥并按桥的价格计费。
  3. Given 平地上有农业或工业分区，When 周期结算，Then 获得平地产出优势。
  4. Given 住宅靠近河流、湖泊、海岸或森林，When 周期结算，Then 居民满意度提高。
  5. Given 玩家清除森林，When 确认操作，Then 扣除资金并得到平地或原高度的可建设地块。
  6. Given 工业分区覆盖矿产，When 周期结算，Then 获得矿产原料。
- 业务规则：
  - 不同地形要形成不同专长，不能让某类城市明显吃亏；数值见 Q-006，矿产种类见 Q-011。
  - 森林可以清除，其他地形不能改变。
  - 矿产不要求每座城市都有。
- 边界和异常：
  - 地块同时有矿产和森林：先清除森林才能开采。
  - 资金不足以修桥或清除森林：拒绝操作并显示所需资金。
