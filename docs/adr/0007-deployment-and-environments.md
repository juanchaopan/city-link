# ADR-0007 部署和环境

- 状态：已接受
- 日期：2026-10-30
- 相关需求：REQ-026、REQ-027

## 背景

云开发免费体验只包含一个环境，微信小游戏也不能为每个 PR 生成预览。项目需要低成本的开发、预览和发布流程。

## 候选方案

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| 一个云环境加本地内存后端 | 不额外花钱，开发和 PR 预览都不用云资源 | 上线后没有独立测试环境 | 尽量零成本 |
| 测试和生产各一个云环境 | 后端改动可以先验证 | 每月多一份套餐费用 | 有收入或玩家较多时 |

## 决策

| 环境 | 内容 | 部署方式 |
|---|---|---|
| 本地 | 网页版加内存后端 | `pnpm dev` |
| PR 预览 | 网页版静态文件加内存后端 | 每个 PR 部署到 Cloudflare Pages |
| 体验版 | 微信体验版，连接唯一的云环境 | 推送 `v*` 标签后，CI 部署云函数并用 miniprogram-ci 上传 |
| 线上版 | 微信线上版，连接同一云环境 | 维护者在微信后台提审和发布 |

分支策略用 GitHub Flow。云函数部署和体验版上传只由标签触发，生产部署由维护者决定。回滚时重新部署上一标签的云函数，小游戏回退到上一线上版本。公开测试后如果需要频繁改后端，再增加测试环境。

## 证据

无。

## 后果

- 好处：开发期没有云成本，PR 预览可以直接打开。
- 代价：内存后端不能发现平台问题，所以发布前要跑 Q-008 的集成脚本；上线后体验版和线上版共用数据，测试账号要标记并排除出统计。
- 什么时候应该重新考虑：出现一次由后端改动引起的线上事故，或玩家超过 1000 日活。
