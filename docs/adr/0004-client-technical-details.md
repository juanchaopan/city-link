# ADR-0004 客户端的技术细节

- 状态：已接受
- 日期：2026-10-30
- 相关需求：REQ-001、REQ-022、REQ-028

## 背景

规范库没有 PixiJS 技术栈，这里按类别列出客户端的决策，/scaffold 要照此补一套规范。

## 候选方案

| 类别 | 选择 | 放弃 | 理由 |
|---|---|---|---|
| 仓库和包管理 | pnpm 单仓库 | npm 工作区 | 多包共用依赖更严格 |
| 构建 | Vite，网页和微信两个构建目标 | esbuild 自写脚本 | 有开发服务器和热更新 |
| UI | @pixi/ui 加 @pixi/layout | 自写组件 | 开发最快；要在真机验证 |
| 状态管理 | 自写的 TypeScript 状态容器 | 状态管理库 | 模拟循环要控制更新频率 |
| 项目分层 | `platform`、`net`、`game`、`render`、`ui` | 按页面分 | 让渲染可以被替换 |
| 地图渲染 | 16×16 分块，ParticleContainer | 每对象一个 Sprite | 探针显示 Sprite 方式只有约 4 帧 |
| 素材 | 脚本生成图集，按主题分包放云存储 | 全部进包 | 主包受限 |
| 屏幕方向 | 竖屏 | 横屏 | 可见地块接近，单手更方便 |
| 测试 | Vitest | Jest | 和 Vite 共用配置 |
| 视觉测试 | Playwright | 无 | 见 ADR-0008 |
| lint 和格式化 | ESLint、typescript-eslint、Prettier | Biome | 和规范库的 Node 技术栈一致 |
| 架构检查 | dependency-cruiser | 无 | 和规范库一致 |
| TypeScript | 6.x | 7.x | 规范库注明工具链暂不支持 7 |

## 决策

采用上表的选择。模拟循环和渲染分开：模拟按固定步长运行，渲染按帧读取只读状态，路网计算按帧分摊。

## 证据

分块和 Sprite 的对比见 ADR-0003。竖屏是产品判断，没有留存对比数据，来源为 AI 建议，用户默认。

## 后果

- 好处：工具和服务端一致，AI 可以在浏览器里完成大部分验证。
- 代价：/scaffold 要新建一套 PixiJS 规范和架构检查规则。
- 什么时候应该重新考虑：ADR-0003 被否决时。
