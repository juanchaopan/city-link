# ADR-0002 单入口模块化单体和共用规则库

- 状态：已接受
- 日期：2026-10-30
- 相关需求：REQ-021、REQ-022、REQ-027

## 背景

项目由一个人加 AI 维护，第一年日活 1000 到 1 万，成本要接近 0。城市模拟要在手机上运行，服务端又要校验结果，所以两端必须使用同一套规则。维护者熟悉 Java 和 TypeScript。

## 候选方案

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| 单入口模块化单体 | 部署和排错最简单，模块间可以直接调用 | 模块边界要靠架构检查保证 | 维护人力少 |
| 按领域拆多个云函数 | 故障和扩容相互隔离 | 部署多，冷启动多，跨域一致性难 | 不同领域的流量差异大 |
| 服务端权威模拟 | 最防作弊 | 成本高，弱网无法建造，和 REQ-022 冲突 | 竞技类游戏 |

## 决策

服务端只有一个 `game` 云函数，内部按 identity、world、terrain、city、trade、ops 分模块。全部代码使用 TypeScript，规则放在 `libs/sim`，客户端和服务端共用。Java 不进入这个项目，否则规则要写两份。

## 证据

无。

## 后果

- 好处：只需要部署一个函数，规则只写一份，AI 能在一个仓库里完成全部改动。
- 代价：结算和玩家请求共用函数配额；模块边界需要 dependency-cruiser 强制。
- 什么时候应该重新考虑：结算影响玩家请求，或日活持续超过 1 万。
