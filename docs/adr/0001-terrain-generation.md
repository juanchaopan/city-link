# ADR-0001 地形生成和线路规则

- 状态：已接受
- 日期：2026-10-30
- 相关需求：REQ-003、REQ-013、REQ-033、REQ-034

## 背景

位置第一次被玩家占用时，服务端要生成山丘、平地、河流、湖泊、森林、海岸和矿产，并和相邻位置完全接上。地形还要保证中心平地、可建面积和全部连接点，单次生成要足够快，存储要足够小。地形有真实高度，八方向线路在坡地和水面上的规则决定了 2.5D 素材量。

## 候选方案

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| 64×64，4 层，全部坡地和桥都走八方向，直坡用切坡路基 | 规划最自由，玩家不用记例外规则；路面水平，车是正的 | 素材最多，还要画挡墙和填方 | 优先保证规划感 |
| 64×64，4 层，全部坡地走八方向，路面贴坡 | 最容易画 | 车看起来是歪的 | 不在意细节 |
| 64×64，4 层，只有角形坡和桥走斜向 | 路面不侧倾 | 约 55% 的坡地是直坡，不能走斜线 | 想省素材 |
| 64×64，4 层，坡上和桥只走水平、垂直 | 素材最少 | 坡上和过河失去斜线 | 素材成本优先 |
| 64×64，3 层 | 素材更少，可建面积多 2.6 个百分点 | 起伏变弱 | 地形只作为背景 |
| 128×128 | 城市更大 | 生成更慢，真机压力未知 | 真机性能有余量时 |

## 决策

采用城市地图 64×64、4 层高度，全部坡地和桥都走八方向。直坡上的 45° 斜路用切坡路基：路面保持水平，上下两侧用挡墙和填方接地形。样图见 `docs/adr/assets/q014-slope-road-samples.png`。路基用分层拼接绘制。

生成方法：
- 高度、森林和河流走向按全群坐标取噪声，相邻城市的纹理自然连续。
- 共享边界固定后，用切比雪夫距离的约束传播把相邻高度差限制在 1 层内。
- 共享边界的角点使用角点平台，避免两条边界在角上冲突。
- 河流只在最低层，走向和宽度由 ADR-0009 的河网骨架决定，并避开共享边界。
- 河流不能穿过新手走廊，湖泊只保留和中心连通的部分。

可建面积保底定为 60%，来源为 AI 建议，用户默认。

线路规则：转向只在平地发生，坡上和桥上保持方向；鞍形地块线路不能通过；桥单段最长跨 5 个水体地块，桥不阻挡船只。

## 证据

地形探针第三轮，64×64，3 层和 4 层各 1920 座城市，环境是 AMD Ryzen 9 7940HS 上的 Node v24.22.1：

| 指标 | 3 层 | 4 层 |
|---|---|---|
| 硬失败 | 0 | 0 |
| 边界、高度差、水位违规 | 0 | 0 |
| 可建面积 平均 / 最小 | 84.7% / 70.5% | 82.1% / 66.0% |
| 首笔贸易 / 全部连通失败 | 0 / 0 | 0 / 0 |
| 生成 P50 / P95 / 最大 | 20.7 / 26.3 / 130 毫秒 | 15.4 / 21.9 / 87 毫秒 |
| 每城存储 gzip 平均 | 550 字节 | 592 字节 |

全部 6528 座城市都没有硬失败；没有角点平台时，3 层和 4 层各有 19 座和 31 座失败。加入河网后的结果见 ADR-0009。

地形和线路素材估算约 230 张，不含建筑、高速互通口和水运，都没有实际制作。其中 48 种坡地和轴线组合有 36 种需要路基；分层拼接用 40 张，逐形状整张绘制要 108 张。

证据文件：`docs/adr/assets/terrain-spike.md`、`docs/adr/assets/terrain-results.json`、`docs/adr/assets/terrain-cluster-L4.png`、`docs/adr/assets/q014-slope-road-samples.png`。探针代码归档在标签 `archive/spike-terrain`。

## 后果

- 好处：城市地形连续且各不相同，玩家在任何地形上都能用同样的八方向规则规划；存储小，生成快。
- 代价：线路和地块素材比最省方案多约 80 张；切坡路基的最终美术还没有验证，样图只是几何示意；增加了 2026 年 11 月 30 日目标的风险。
- 什么时候应该重新考虑：切坡路基的实际画面不可接受，此时退回角形坡方案，地形数据不用改；素材制作进度威胁到上线时间；真机无法流畅渲染 64×64。
