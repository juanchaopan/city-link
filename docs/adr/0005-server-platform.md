# ADR-0005 服务端使用微信云开发云函数

- 状态：提议
- 日期：2026-10-31
- 相关需求：REQ-014、REQ-019、REQ-021、REQ-024、REQ-027、REQ-033

## 背景

多人贸易需要服务端，维护者只有一人。现行文档写个人版环境 QPS 500、函数超时最大 900 秒。开发阶段可以使用免费的个人版，含 40,000 资源点/月；付费个人版约 19.9 元/月，额度相同。免费环境在小程序发布后第 15 天到期，到期后进入隔离期，不转付费就会被销毁。

## 候选方案

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| 云开发云函数 | 自带微信身份，几乎没有运维，有定时触发器和事务 | 按调用计费，文档型数据库，绑定微信 | 上线初期规模小 |
| 云托管容器 | 可以用 Fastify，常驻进程，迁移容易 | 按资源计费，数据库单独准备 | 需要常驻连接 |
| 自建云主机 | 技术最自由，可用 PostgreSQL | 固定月费，要管备份、安全和备案 | 有运维时间 |

## 决策

用户选择云开发云函数和云数据库。`game` 函数同时处理客户端请求和一个每 5 分钟的定时触发器，用 `action` 路由。数据访问走 repository 接口，有云开发和内存两套实现。服务端不用 Web 框架，校验使用 zod，测试使用 Vitest，架构检查使用 dependency-cruiser。

环境 ID 是 `cloud1-d4g50k8p5a564b091`，开发阶段使用免费个人版，超限按量付费关闭。云函数部署后要在控制台把超时调大，默认 3 秒，部署命令不会改它。

这项决策要等费用实测后才接受。还没验证的判据：
- 资源点实际折算：查询和未命中的条件更新各算几次调用，统计可能延迟 2 天。
- 模拟规模下的实际费用和 ADR-0006 的估算一致。
- 地形生成冷启动时的总耗时。探针测的是热启动，冷启动 ping 另外测得约 0.94 秒。
- 更高并发：100 以上没有测完。

失败时先延长同步和结算周期，仍不够时改用云托管，repository 接口保持不变。

## 证据

真实环境探测，2026-10-31，从开发者工具模拟器调用云函数：

| 判据 | 结果 |
|---|---|
| 单文档条件更新原子性 | 20 个并发更新，`final` 和 `updated` 都是 5，符合预期 |
| 相同 `_id` 并发写入 | 10 个并发只成功 1 个，符合预期 |
| 数据库读 | P50 27 毫秒，P95 53 毫秒，最大 67 毫秒 |
| 数据库写 | P50 36 毫秒，P95 59 毫秒，最大 63 毫秒 |
| 排序查询 | P50 29 毫秒，P95 38 毫秒，最大 45 毫秒 |
| 冷启动 | 首次调用 937 毫秒 |
| 地形生成（热启动） | 函数内 133 到 371 毫秒，客户端往返 724 到 934 毫秒 |
| 并发调用 | 10、20、50、100 全部成功；100 个用时 35.2 秒，主要受模拟器客户端限制，不等于服务端上限 |

探测用的是不含河网骨架的旧版地形算法。云函数里的生成耗时约是本机的 10 倍，加入河网后要在实现时重新测量。

模拟费用，按内存实现推算：

| 方案 | 1000 日活 | 1 万日活 |
|---|---|---|
| 最初方案 | 约 300 元/月 | 约 3092 元/月 |
| 只结算活跃连接（采用，见 ADR-0006） | 约 35 元/月 | 约 518 元/月 |

1 万日活实际模拟到约 8970，数字约低估 10%。其中 CDN 约 101 元，取决于 12MB 素材的假设。其他假设和官方原文见 `docs/adr/assets/cloudbase-summary.json` 和探针分支。

## 后果

- 好处：几乎不用运维，身份和分享自然打通；结算依赖的条件更新和唯一写入已经验证；数据库延迟足够低。
- 代价：绑定微信平台；费用随日活线性增长，约 2200 日活就到 100 元/月；发布前要转付费环境；本地没有官方模拟环境，所以要靠内存后端和真实环境验证两层保证；个人版有没有数据回档仍未确认。
- 什么时候应该重新考虑：资源点实测远高于估算，或费用超过 REQ-027 的上限。
