# ADR-0005 服务端使用微信云开发云函数

- 状态：提议
- 日期：2026-10-30
- 相关需求：REQ-014、REQ-019、REQ-021、REQ-024、REQ-027、REQ-033

## 背景

多人贸易需要服务端，维护者只有一人。现行文档写个人版环境 QPS 500、函数超时最大 900 秒，基础套餐约 19.9 元/月，含 40,000 资源点。免费环境在小程序发布后第 15 天到期，到期后进入隔离期，不转付费就会被销毁。

## 候选方案

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| 云开发云函数 | 自带微信身份，几乎没有运维，有定时触发器和事务 | 按调用计费，文档型数据库，绑定微信 | 上线初期规模小 |
| 云托管容器 | 可以用 Fastify，常驻进程，迁移容易 | 按资源计费，数据库单独准备 | 需要常驻连接 |
| 自建云主机 | 技术最自由，可用 PostgreSQL | 固定月费，要管备份、安全和备案 | 有运维时间 |

## 决策

用户选择云开发云函数和云数据库。`game` 函数同时处理客户端请求和一个每 5 分钟的定时触发器，用 `action` 路由。数据访问走 repository 接口，有云开发和内存两套实现。服务端不用 Web 框架，校验使用 zod，测试使用 Vitest，架构检查使用 dependency-cruiser。

这项决策要等真实环境验证通过后才接受。真实环境判据：
- 确认基础套餐的 QPS、并发、超时和资源点折算。
- 单文档条件更新是原子的，相同 `_id` 并发写入只成功一个。
- 地形生成含冷启动 P95 不超过 2 秒。
- 模拟规模下的实际费用和 ADR-0006 的估算一致。

失败时先延长同步和结算周期，仍不够时改用云托管，repository 接口保持不变。验证步骤见探针分支 `spike/cloudbase` 的 `spikes/cloudbase/SPIKE.md`。

## 证据

探针没有上云，只核实了官方文档并用内存实现模拟。

| 方案 | 1000 日活 | 1 万日活 |
|---|---|---|
| 最初方案 | 约 300 元/月 | 约 3092 元/月 |
| 只结算活跃连接（采用，见 ADR-0006） | 约 35 元/月 | 约 518 元/月 |

1 万日活实际模拟到约 8970，数字约低估 10%。其中 CDN 约 101 元，取决于 12MB 素材的假设。模拟峰值约 339 次/秒，低于 500；文档没有说明云函数内的数据库调用是否计入 QPS。其他假设和官方原文见 `docs/adr/assets/cloudbase-summary.json` 和探针分支。

## 后果

- 好处：几乎不用运维，身份和分享自然打通。
- 代价：绑定微信平台；费用随日活线性增长，约 2200 日活就到 100 元/月；免费环境发布后第 15 天到期，上线前要转付费；本地没有官方模拟环境，所以要靠内存后端和真实环境验证两层保证；探针的文档有两处矛盾未解决：免费环境是 40,000 点还是 3000 点，个人版有没有数据回档。
- 什么时候应该重新考虑：真实环境不达标，或费用超过 REQ-027 的上限。
