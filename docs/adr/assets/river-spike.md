# 探针：河网骨架是否可行（ADR-0009、Q-015）

这是探针代码，只用来回答问题，永远不合并进正式代码。

## 要回答的问题

城市群创建时先生成河网骨架，再在首次占用时按骨架生成地形，能否做到至少 70% 的位置有河、干流连通，同时保住可建面积和全部连接点？回归城市带着旧河道时怎么和骨架配合？内河路线和码头在这张河网上能否成立？

## 判据

R1 到 R8 来自 ADR-0009 和指令，没有放宽。R9、R10 的数字是探针自己定的，用户还没有确认，见"待用户确认的判据"。R11 到 R13 是第四轮指令要求的。

## 时间盒

## 回归城市

第三轮要求骨架签名完全相同，1 座 `t-t-` 找不到位置，几乎所有城市都进了新建城市群。第四轮换成新规则：

1. 候选位置要满足：8 个相邻位置都没有地形；贴外边界的城市回到同一方向、同类型的外边界。
2. 把这个位置四条边改成回归城市的河流接口，邻居的边跟着改。这些邻居都没有地形，改动只碰骨架。
3. 校验改写后的骨架：干流连通、每个有河位置都连到干流网、有河位置不少于 70%、邻居不超过 3 个口。
4. 选改动边数最少的位置。依次试 8 个开放城市群，都不行才新建城市群。

实测放好后把城市群占满，见 `out/returning.json`：

## 连接点

规则改成：除鞍形地块外，所有坡地都能走八个方向，转向只在平地，桥可以走斜线。1920 座城市首笔贸易失败 0，全部连通失败 0。

## 耗时

1055 毫秒是第三轮的最大值，在其他探针同时运行时测到。查证结果：

| 项目 | 结果 |
|---|---|
| 同一批城市重跑 3 遍（5760 次生成） | 每遍 P50 19.9、17.7、18.3；P95 36.5、32.8、32.5；P99 48、46、45；最大 110、72、99 毫秒 |
| 超过 1 秒的次数 | 0，没有复现 |
| 重试 | 0，每座城都是 1 次生成 |
| 垃圾回收 | 单次最长 37 毫秒，5760 次生成里总共 1.3 秒 |
| 河道雕刻 | P95 18 到 21，最大 85 毫秒 |
| 道路搜索 | P95 14 到 15，最大 39 毫秒 |
| CPU 占满时（48 个忙循环） | P50 353，P95 850，最大 2940 毫秒，640 次里 388 次超过 200 毫秒 |
| 同一轮未占满时 | P50 19，P95 35，最大 70 毫秒 |

判断：算法本身的上限约 60 到 75 毫秒，这是路点全部试满时的结果，3 遍里都较慢。其余尖峰来自 JIT 预热和垃圾回收。1055 毫秒最可能来自当时的 CPU 争用，这是对照实验支持的推断，当时没有采样，不能直接证明。

对云函数的含义：CPU 配额紧时耗时会放大一个数量级，Q-008 要实测。

## 内河路线

码头占 3×2 平地，长边贴岸，必须贴在和干流相连的通航水上；孤立的湖不算。路线按 3×3 通航格 8 邻接搜索。

| 指标 | 结果 |
|---|---|
| 有码头位置的干流城市 | 909 / 909 |
| 每城可建码头的岸线长度 | 平均 164 格，P5 77 格，最小 27 格，最大 334 格 |
| 每城码头摆放位置 | 平均 103 个，P5 48 个，最小 16 个 |
| 随机城市对路线 | 900 条，失败 0 |
| 路线长度 | 平均 577 格，最长 1624 格，平均途经 6.7 座城 |
| 按骨架算的城市序列和实际河道不一致 | 0 / 900 |
| 每城可修桥的跨河位置 | 平均 372 个，最少 50 个 |
| 桥下可通行时连通 | 909 / 909 |
| 对照：同样 1818 座桥如果挡船 | 只剩 55 / 909 连通 |

结论：
- 路线可以只按骨架算，大多数位置还没有地形也能算，途经城市列表和实际河道完全一致。
- 桥下必须可以通行。如果桥挡船，每城两座桥就会把干流截成碎片，所以水运判定要把桥当作不存在。

## 素材估算

这是估算，没有实际制作和渲染。依据在 `out/assets.json`。其中 `junctionTiles` 数的是宽水面格子，不是汇流口，不作依据。

实测依据：
- 河岸用四角水陆组合（双网格）拼接，8 个城市群里 16 种全部出现，3 格宽和 1 格宽可以共用。
- 海岸只出现 9 种组合。
- 河岸几乎都是平地：贴水的陆地 82309 格是平地，88 格是坡地，不需要"坡上河岸"素材。

| 项目 | 估算张数 | 算法 |
|---|---|---|
| 3 格河岸、湖岸 | 0 | 共用已计入的 16 张水岸 |
| 汇流口 | 4 | 拼接已能表现，加 4 张点缀 |
| 河口 | 4 | 河入海的 4 个方向 |
| 内河码头 | 8 | 2 个朝向镜像 × 2 个等级，加 4 张栈桥和吊机 |
| 海港 | 8 | 4 个海岸方向 × 2 个等级 |
| 国际港 | 8 | 4 个海岸方向 × 2 个等级 |
| 船 | 15 | 3 种船 × 5 个方向，其余 3 个方向镜像 |
| 水运小计 | 47 | |

切坡路基：12 种可走的坡地 × 4 条轴线共 48 种组合。已有素材覆盖 12 种（4 种顺坡直道和 8 种角形斜道）。其余 36 种在 1920 座城的最短路径里全部出现，占坡上路段 64%。ADR-0001 的 214 张只为其中 8 种算了素材。

| 做法 | 素材 | 地形和线路合计 | 说明 |

## 判断

ADR-0009 的方案可行，R1 到 R13 全部通过。是否接受由用户决定。

建议参数见 `params.js`：干流位置 45%，有河位置 80%，干流 3 格，支流 1 格，路线离障碍 4 格，新手走廊半宽 3 格，河边低地 3 格，可建面积保底 60%，湖泊半径 8 到 12 格按空间收缩，边界口偏移 8 到 21 或 43 到 55，对边的口至少错开 14 格，蜿蜒幅度 1.8 到 3 格、波长 22 到 34 格，路点最多试 6 次。

回归规则：依次试 8 个开放城市群，选改动边数最少的位置，都不行再新建城市群，新建时换种子。
