# ADR-0009 河网和水运

- 状态：已接受
- 日期：2026-10-30
- 修改日期：2026-11-14
- 相关需求：REQ-011、REQ-015、REQ-033、REQ-034、REQ-036、REQ-038；设计稿 `docs/design/game-design.md` 第 2、9、15 节

## 背景

设计稿要求每座城市至少有一条能通航的河从城里穿过，并经河网连到本地区的其他城市和别的地区。水运是邻居不玩了以后谁也挡不住的那条路：卖得便宜，但永远走得通。河网还要经过空白位置，因为位置随时可能有人住进来。

地区是 4×4 的位置，国家由若干地区拼成。河要能跨过地区边界，而高速公路和铁路只能经陆路口岸跨地区。

## 候选方案

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| 按国家生成一张河网，流过每个位置 | 河一定连通，大河能跨地区；水运选路只用河网，不需要邻居的地形 | 河网要和每个位置的地形生成配合 | 河是货运通道 |
| 按地区各生成一张 | 地区之间互不影响 | 河在地区边界上断开，或者要另外对齐 | 水运只在地区内 |
| 相邻位置逐个贴合 | 不用单独的河网算法 | 不保证连通，也不保证每个位置都有河 | 河只是地貌 |

## 决策

**河网按国家生成。**

- 全国一张河网，像一棵分叉的树，是一棵经过全国每个位置的生成树，流过每一个位置，包括空白位置。大河跨地区。
- 河网存在 river_network（country_id、paths、slot_entries）：paths 是全国坐标下的折线，slot_entries 记每个位置的河从哪进、从哪出，水运选路用它。表见 `docs/design/data-model.md` 第 2 节。
- 生成地形时（ADR-0001）按河网把河刻进每个位置；能通航的河按通航河宽刻，地形文件用 navigable 标出能通航的河段。每座城市至少有一条能通航的河穿城，并经能通航的河段连到本地区的其他城市和别的地区；不要求通到四个方向的邻居。
- 河是地形，谁也拆不掉。桥从河上跨过不挡船；湖和海不架桥；通航河的每一段每隔不超过若干格就有一处两岸平地、能架桥。

**河跨地区的地方不设口岸。** 船照常走，没有特殊规则。货从本城的码头出地区：出地区时码头就是出口节点，所以水运过路费只在地区内收。

**水运**（`game-design.md` 第 9 节）：

- 内河码头 2 级解锁，造在本城任何一段能通航的河边，什么货都能运。
- 有码头的城市就能沿河把货卖给本地区任何有码头的城市。中间经过的城市什么都不用造，按水运费率收过路费；经过空白位置时照样能走，空白位置不收费。
- 地区结算时，水运两端都要有码头，按 slot_entries 走，不需要已核路网和邻居的地形。
- 走水运卖出去的部分按水运折扣计入售出率。水运折扣明显大于穿过一两座城市的过路费，这样有陆路时陆路划算，但水运永远值得用。选路的代价算上过路费、拥堵和折扣，水运是没有别的路时的保底。
- 水运不算游客的连通。

**海**：国际港 10 级解锁，只能造在海边，只通外国市场。国内的货不走海港，内陆城市没有国际港，四星的货靠 9 级的国际机场出口。港口的出口折扣比机场小，所以国外的货优先走港口。

**由 #23 地形探针定的参数**：通航河宽（设计稿给的范围是 4 到 6 格）、桥的最大跨度（不小于通航河最宽处加 2 格）、能架桥的位置的最大间隔、每个位置都有通航河、可建面积保底。结果写进本 ADR 和 ADR-0001 的新版本。

## 证据

### 64 格探针（历史数据）

探针四轮，64 格地图、4 层，共 1920 个位置，机器为 AMD Ryzen 9 7940HS，Node v24.22.1。当时的河网按若干位置一组生成，干流 3 格宽可通航，支流 1 格宽不通航，约 45% 的位置有干流、80% 的位置有河。下面的结果说明生成树式的河网在连通、接缝和耗时上可行；比例和宽度不用于 256 格。

| 判据 | 结果 |
|---|---|
| 硬失败 | 0，没有重试 |
| 接缝违规 | 0 |
| 有河位置 ≥70% | 79.7% |
| 干流连通 | 909 / 909 |
| 河流不断 | 3000 个河口断开 0 个 |
| 可建面积 ≥60% | 平均 78.2%，最小 60.9% |
| 生成耗时 P95 ≤100 毫秒 | 32 到 36 毫秒，P99 45 到 48 毫秒，最大 72 到 110 毫秒 |
| 明显直角 <0.5 个/100 格 | 干流 0.12，支流 0.13 |
| 回环 | 0 |
| 长直段 P95 ≤30 格 | 干流 25，支流 23，最大 36 |
| 内河路线 | 900 条全部算出，平均 577 格，平均途经 6.7 个位置 |
| 码头位置 | 909 个有干流的位置全部有，平均 103 个，最少 16 个 |
| 桥下通行 | 909 / 909 连通；桥挡船时只剩 55 / 909 |

直角、回环和长直段的算法见 `docs/adr/assets/river-spike.md`，由用户根据 `docs/adr/assets/river-confirm.png` 确认。

| 位置类型 | 数量 | 水体平均 | 可建面积平均 | 可建面积最小 |
|---|---|---|---|---|
| 有干流 | 909 | 10.6% | 74.1% | 60.9% |
| 只有支流 | 621 | 4.2% | 80.6% | 64.1% |
| 无河 | 390 | 2.0% | 84.3% | 72.3% |

有干流的位置比无河的平均少 10.2 个百分点可建面积。CPU 被占满时，生成 P95 约 850 毫秒，最大约 2940 毫秒。

证据文件：`docs/adr/assets/river-spike.md`、`docs/adr/assets/river-results.json`、`docs/adr/assets/river-confirm.png`。探针代码和参数归档在标签 `archive/spike-river-network`。

### 256 格

还没有实测，由 #23 量：每个位置都有通航河、可建面积不低于保底、桥能跨过每一处通航河。

## 后果

- 好处：每座城市都有一条谁也挡不住的货运通道；河网连通有保证，水运选路不依赖邻居的地形；河跨地区不用额外的口岸规则。
- 代价：河把平地切碎，河网汇合处的位置可建地更少，要靠水运过路费和位置平衡来补（设计稿第 2 节“位置的平衡”，数值在 Q-006）；每个位置都要有通航河，地形生成的验收更难通过。
- 尚未验证：256 格的河宽、桥跨和可建面积；水运的折扣和费率；2.5D 下河流和湖泊的观感。
- 什么时候应该重新考虑：#23 探针在 256 格上做不到每个位置都有通航河且可建面积不低于保底；或者内测发现水运挤压了陆路货运。
