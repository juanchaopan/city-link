# ADR-0008 视觉验证方式

- 状态：已接受
- 日期：2026-10-30
- 相关需求：REQ-003、REQ-033、REQ-034

## 背景

项目没有设计稿，游戏画面由 Pixi 绘制，主要由 AI 开发。2.5D 素材量大，拼接错误靠人工很难发现。

## 候选方案

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| 效果页加截图回归 | 自动发现画面被改坏，适合 AI 自检 | 要维护基准图 | 素材和规则都多 |
| 只用真机人工验证 | 不用维护 | 问题发现晚，占用维护者时间 | 画面简单 |

## 决策

用网页版提供一个 `gallery` 效果页，用固定种子渲染道路、高速、铁路、桥、坡地、河流、码头、建筑和界面。Playwright 在官方镜像里截图并和基准比较，失败的 PR 不能合并。视觉规范放在 `apps/client/src/ui/tokens.ts`，界面只引用令牌。

Pixi 使用 WebGL，截图对比用软件渲染，会设置少量容差。不使用 Storybook，效果页代替它展示组件。关键版本再用真机人工检查。

## 证据

无。

## 后果

- 好处：每种素材组合都能被自动检查，也能提供给 PR 预览查看。
- 代价：改美术时要更新基准图；网页截图不能代表微信真机，真机检查仍然必要。
- 什么时候应该重新考虑：基准图的维护成本超过它发现的问题。
