# 按游戏设计稿调整需求和架构

- 日期：2026-11-04
- 级别：L4 架构变了（目标和需求也一起变了）；设计冲击 D0（游戏规则的业务代码还没有写）
- 来源：2026-11-03 和用户逐项问答整理出的游戏设计稿：`docs/design/game-design.md`、`data-model.md`、`catalog.md`、`ui-map.md`，待用户确认

## 变了什么

游戏设计稿把怎么玩定到了能开发的程度，和早先写的需求、架构有大面积出入。主要几处：

- 世界从“64 城的城市群”变成“国家 → 4×4 的地区 → 256×256 格的城市”；新玩家按顺序填最前面的空位；没有系统城市，没人的位置是空白。
- 一个玩家只经营一座城市，从 1 级开始；想换地方要先结束这一座再开新城，结束的城市成为历史城市。
- 不设配额贸易：本城内部的买卖由手机算，城市之间的货运由服务端按地区每个游戏日算一次，全国需求按国家汇总，外国市场由系统模拟。
- 只有高速公路和铁路能接邻居；线头就是请求，对方要在 7 天内接好，否则城市结束。
- 收入以激励视频为主，不限次数；允许资金为负，按红线和破产保护处理，没有救济金。
- 取消好友航线和国内海港；改规划时征收不花钱。

## 为什么

需求和架构写在游戏规则定下来之前，按它们无法开工。设计稿里每条规则都和用户逐项确认过，冲突时以设计稿为准，需求和架构文档跟着改。
